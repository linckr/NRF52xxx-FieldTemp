# 蓝牙技术方案 1.1

本文档描述 `blinky_3` 当前固件实现的 **BLE GATT 通讯协议接口**（服务/特征/数据格式/读写与通知规则）。

> 说明：本文档以 `src/main.c` 为准；所有多字节字段均为 **小端序（Little-Endian）**。

## 1. 广播（Advertising）

- **设备名**：`CONFIG_BT_DEVICE_NAME`（广播包中 `Complete Local Name`）
- **Flags**：`LE General Discoverable` + `BR/EDR Not Supported`
- **广播数据**：仅包含设备名称和标志位，不携带服务 UUID

> 扫描响应包 `sd[]` 为空。

## 2. 连接与安全

- **连接类型**：可连接广播（Connectable）
- **配对/绑定**：当前实现未做配对/绑定流程（按现有代码逻辑，客户端可直接读写/订阅）。

## 3. GATT 服务与特征一览

### 3.1 实时数据服务（自定义 128-bit UUID）

- **Service UUID**：`12340030-1234-5678-1234-56789ABCDEF0`

#### 3.1.1 实时数据（Realtime Data）

- **Characteristic UUID**：`12340031-1234-5678-1234-56789ABCDEF0`
- **属性**：Read + Notify
- **数据格式**：6 字节（小端序）
  - `temperature`：`int16`（LE），温度，单位 **0.01°C**
  - `humidity`：`uint16`（LE），湿度，单位 **0.01%RH**
  - `pressure_dhpa`：`uint16`（LE），气压，单位 **0.1 hPa**
- **Read 行为**：读取时**立即从传感器获取当前实时值**（同时读取温度、湿度、气压三个传感器）
- **Notify 行为**：按采集间隔推送更新（包含温度+湿度+气压的完整数据）

> 说明：此服务将温度、湿度、气压合并为一个特征，客户端一次读取即可获取所有实时数据，比分别读取三个特征更高效。

---

### 3.2 配置服务（自定义 128-bit UUID）

- **Service UUID**：`12340020-1234-5678-1234-56789ABCDEF0`

#### 3.2.1 采集间隔（Sample Interval）

- **Characteristic UUID**：`12340021-1234-5678-1234-56789ABCDEF0`
- **属性**：Read + Write
- **数据格式**：`uint16`（秒）
- **约束**：
  - 最小：`1`
  - 最大：`3600`

#### 3.2.2 当前状态（Device Status）

- **Characteristic UUID**：`12340022-1234-5678-1234-56789ABCDEF0`
- **属性**：Read + Notify
- **数据格式**：8 字节
  - `interval_sec`：`uint16`（LE）采集间隔秒
  - `record_count`：`uint16`（LE）采集计数（固件内部计数）
  - `flags`：`uint8`
    - bit0：蓝牙已连接（1=connected）
    - bit1：时间已同步（1=time_synced）
    - bit2：清空数据进行中（1=data_clear_in_progress）
  - `reserved`：`uint8`，固定为 0
  - `firmware_version`：`uint16`（LE）固件版本号

#### 3.2.3 历史数据（History Data）

- **Characteristic UUID**：`12340023-1234-5678-1234-56789ABCDEF0`
- **属性**：Notify + Write
- **用途**：
  - Write：设置“起始时间戳”过滤条件
  - Notify：分包发送历史记录

**Write（客户端 → 设备）：起始时间戳**

- **数据长度**：4 字节
- **数据格式**：`uint32`（LE），Unix 时间戳（秒）
  - `0`：发送全部历史记录
  - `>0`：仅发送 `timestamp > start_timestamp` 的记录

**Notify（设备 → 客户端）：历史记录流**

- **每条记录大小**：12 字节（与 `struct data_record` 一致）
- **记录格式**（12 字节，小端序）：
  - `timestamp`：`uint32`（LE），Unix 时间戳（秒）
  - `temp_raw`：`int16`（LE），温度（单位 0.01°C）
  - `hum_raw`：`uint16`（LE），湿度（单位 0.01%RH）
  - `pressure_centihpa`：`uint32`（LE），气压（单位 0.01 hPa），直接存储 Pa 值

> 说明：气压精度从 0.1 hPa 提升到 0.01 hPa，可检测约 8.5 厘米的高度变化。

- **分包方式**：
  - 通常每个通知包携带 **5 条记录**（即 60 字节，5 * 12 = 60）
  - 传输结束时，设备会额外发送 **1 字节 `0xFF`** 作为结束标志（单独一个 Notify）

> 注意：如果设备尚未完成时间同步，`timestamp` 可能为 `0`，此时“按时间戳过滤”将无法得到预期效果。

#### 3.2.4 时间同步（Time Sync）

- **Characteristic UUID**：`12340011-1234-5678-1234-56789ABCDEF0`
- **属性**：Write
- **数据长度**：4 字节
- **数据格式**：`uint32`（LE），Unix 时间戳（秒）
- **说明**：写入后设备用于生成后续采样记录的 `timestamp`（基于 uptime 推进）。

> 代码里存在 `12340010-...` 的“时间同步服务 UUID”定义，但当前 GATT 中实际只实现了上述 **时间同步特征**，并放在“配置服务”下。

#### 3.2.5 最高/最低温度（Temperature Range）

- **Characteristic UUID**：`12340024-1234-5678-1234-56789ABCDEF0`
- **属性**：Read + Notify
- **数据格式**：4 字节
  - `max_temp`：`int16`（LE），单位 0.01°C
  - `min_temp`：`int16`（LE），单位 0.01°C
- **说明**：设备内部会记录最高/最低温度发生的时间戳（Unix时间戳，秒），并持久化存储到NVS中。时间戳信息可通过设备日志查看，但当前GATT特征中不包含时间戳字段。

#### 3.2.6 重置最高/最低温度（Reset Temperature Range）

- **Characteristic UUID**：`12340025-1234-5678-1234-56789ABCDEF0`
- **属性**：Write
- **行为**：写入任意非空数据触发重置（将最高/最低温度记录及其时间戳清空）。

## 4. 数据采集与存储行为（与协议相关）

### 4.1 实时通知

- 温度/湿度特征：在连接后、客户端订阅 Notify 后推送更新。
- 状态特征：在采集/配置变化时可能通知更新（当前实现未严格检查 CCC 状态，按代码逻辑通知）。

### 4.2 历史记录存储内容（重要）

当前固件版本中，历史存储保存 **温湿度 + 气压**：

- `timestamp`（秒）
- `temp_raw`（int16，0.01°C）
- `hum_raw`（uint16，0.01%RH）
- `pressure_dhpa`（uint16，0.1 hPa）

## 5. 版本记录

### 1.1

- 历史数据记录结构调整为：`timestamp(uint32) + temp(int16) + hum(uint16) + pressure_dhpa(uint16)`（共 10 字节/条）
- 历史发送结束标志：`0xFF`（1 字节 Notify）
- **最高/最低温度时间戳**：设备内部配置结构体（`device_config_t`）增加最高/最低温度发生时间戳字段（各4字节），设备会记录并持久化存储最高/最低温度发生的时间（Unix时间戳，秒）。时间戳信息可通过设备日志查看，GATT特征数据格式保持不变（仍为4字节，仅包含温度值）。
- **固件版本号**：设备内部配置结构体（`device_config_t`）增加固件版本号字段（2字节），当前版本为2。版本号会持久化存储到NVS中，并在"当前状态"特性中返回（数据格式从6字节扩展为8字节，新增`firmware_version`字段）。
