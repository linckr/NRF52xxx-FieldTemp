# 手机端温度计实现方案对比（2026 年）

## 1. 需求分析

### 1.1 核心需求

- ✅ 支持 iOS 和 Android 双平台
- ✅ 无网环境下正常运行
- ✅ 通过蓝牙连接 E104-BT5010A 温湿度采集设备
- ✅ 实时显示温湿度数据
- ✅ 历史数据查看和管理

### 1.2 技术约束

- 设备：E104-BT5010A (nRF52810, BLE 5.0)
- 通讯协议：BLE GATT
- 运行环境：可能无网络连接
- 目标平台：iOS 13+ / Android 8.0+

---

## 2. 技术方案对比

### 方案一：原生 App 开发

#### 2.1 iOS 原生开发 (Swift/SwiftUI)

**技术栈：**

- Swift 5.9+ / SwiftUI
- Core Bluetooth 框架
- Xcode 15+

**优势：**

- ✅ **性能最优**：直接调用系统 API，无中间层损耗
- ✅ **功能完整**：完整访问 iOS 蓝牙 API，支持所有 BLE 特性
- ✅ **用户体验好**：原生 UI，流畅度高
- ✅ **离线运行**：完全本地运行，无需网络
- ✅ **系统集成**：可集成 iOS 通知、后台运行等特性
- ✅ **安全性高**：App Store 审核严格，用户信任度高
- ✅ **长期维护**：Apple 长期支持，API 稳定

**劣势：**

- ❌ **开发成本高**：需要分别开发 iOS 和 Android 版本
- ❌ **开发周期长**：两个平台需要两套代码
- ❌ **维护成本高**：需要维护两套代码库
- ❌ **技能要求高**：需要掌握 Swift 和 Java/Kotlin
- ❌ **发布流程复杂**：需要分别提交 App Store 和 Google Play

**适用场景：**

- 对性能要求极高
- 需要深度系统集成
- 有充足的开发资源
- 长期维护的产品

**开发示例：**

```swift
import CoreBluetooth

class BLEManager: NSObject, CBCentralManagerDelegate, CBPeripheralDelegate {
    var centralManager: CBCentralManager!
    var peripheral: CBPeripheral?

    func startScan() {
        centralManager.scanForPeripherals(withServices: nil, options: nil)
    }

    func centralManager(_ central: CBCentralManager,
                      didDiscover peripheral: CBPeripheral,
                      advertisementData: [String : Any],
                      rssi RSSI: NSNumber) {
        if peripheral.name == "PandaTemperature" {
            self.peripheral = peripheral
            centralManager.connect(peripheral, options: nil)
        }
    }
}
```

**开发示例：**

```kotlin
class BLEManager(context: Context) {
    private val bluetoothAdapter: BluetoothAdapter? =
        (context.getSystemService(Context.BLUETOOTH_SERVICE) as BluetoothManager)
            .adapter

    fun startScan() {
        val scanner = bluetoothAdapter?.bluetoothLeScanner
        val filter = ScanFilter.Builder()
            .setDeviceName("PandaTemperature")
            .build()
        scanner?.startScan(listOf(filter), scanSettings, scanCallback)
    }
}
```

### 方案二：跨平台框架

#### 2.3 React Native

**技术栈：**

- React Native 0.72+
- react-native-ble-plx 或 react-native-ble-manager
- JavaScript/TypeScript

**优势：**

- ✅ **代码复用**：一套代码同时支持 iOS 和 Android
- ✅ **开发效率高**：使用熟悉的 Web 技术栈
- ✅ **热更新**：支持 OTA 更新（需要网络）
- ✅ **生态丰富**：大量第三方库
- ✅ **社区活跃**：Facebook 维护，社区支持好
- ✅ **离线运行**：打包后完全离线运行

**劣势：**

- ❌ **性能略低**：JavaScript 桥接有性能损耗
- ❌ **包体积大**：包含 JavaScript 引擎，体积较大
- ❌ **调试复杂**：需要同时调试原生和 JS 层
- ❌ **BLE 兼容性**：依赖第三方库，可能有兼容性问题
- ❌ **版本更新**：需要跟进 React Native 版本更新

**适用场景：**

- 有 Web 开发经验
- 需要快速开发
- 对性能要求不是极致
- 团队熟悉 JavaScript

**开发示例：**

```javascript
import { BleManager } from "react-native-ble-plx";

const manager = new BleManager();

manager.startDeviceScan(null, null, (error, device) => {
  if (error) {
    console.error(error);
    return;
  }
  if (device.name === "PandaTemperature") {
    manager.stopDeviceScan();
    device
      .connect()
      .then((device) => device.discoverAllServicesAndCharacteristics())
      .then((device) => {
        // 读取温湿度数据
      });
  }
});
```

- 快速原型开发
- 内部工具
- 不需要 iOS 支持

## 5. iOS 应用分发问题（重要）

### 5.1 核心问题

**重要提示：** Flutter 和 React Native 开发的 iOS 应用，**无法在没有 Apple 开发者账号的情况下直接分发给用户安装**。

iOS 系统有严格的安全机制：

- ✅ **Android**：可以直接生成 APK 文件，用户直接安装（无需账号）
- ❌ **iOS**：必须通过 Apple 的签名和分发机制，需要开发者账号

### 5.2 iOS 应用分发方式

#### 方式一：App Store 分发（需要付费开发者账号）

**要求：**

- Apple Developer Program 会员（$99/年）
- 通过 App Store 审核
- 用户从 App Store 下载安装

**优点：**

- ✅ 用户安装方便（从 App Store 搜索下载）
- ✅ 自动更新机制
- ✅ 用户信任度高
- ✅ 无设备数量限制

**缺点：**

- ❌ 需要付费（$99/年）
- ❌ 需要审核（通常 1-3 天）
- ❌ 审核规则严格

---

#### 方式二：TestFlight 内测分发（需要付费开发者账号）

**要求：**

- Apple Developer Program 会员（$99/年）
- 通过 TestFlight 审核（通常比 App Store 宽松）
- 用户需要安装 TestFlight App

**优点：**

- ✅ 可以分发给最多 10,000 名测试用户
- ✅ 审核相对宽松
- ✅ 可以收集反馈和崩溃报告

**缺点：**

- ❌ 需要付费（$99/年）
- ❌ 用户需要安装 TestFlight
- ❌ 测试版本有效期 90 天

---

#### 方式三：企业内部分发（需要企业开发者账号）

**要求：**

- Apple Enterprise Program（$299/年）
- 仅限企业内部员工使用
- 不能对外分发

**优点：**

- ✅ 无设备数量限制
- ✅ 无需 App Store 审核

**缺点：**

- ❌ 费用更高（$299/年）
- ❌ 仅限企业内部使用
- ❌ 申请条件严格（需要 D-U-N-S 编号）

---

#### 方式四：免费开发者账号（个人测试，限制多）

**要求：**

- 免费 Apple ID（无需付费）
- 仅限开发者自己使用
- 需要 Xcode 和 Mac 电脑

**限制：**

- ❌ **只能安装到自己的设备**（最多 3 台设备）
- ❌ **应用有效期 7 天**（7 天后需要重新签名安装）
- ❌ **无法分发给其他用户**
- ❌ 无法使用推送通知等高级功能

**适用场景：**

- 仅用于个人开发测试
- 学习 iOS 开发
- 不适合产品分发

---

#### 方式五：越狱设备安装（不推荐）

**要求：**

- 用户设备需要越狱
- 使用第三方工具安装（如 Cydia Impactor）

**缺点：**

- ❌ 用户设备需要越狱（风险高，不推荐）
- ❌ 违反 Apple 服务条款
- ❌ 安全性问题
- ❌ 普通用户不会越狱

**结论：不推荐此方式**

## 6. 技术实现要点

### 5.1 BLE 连接管理

**关键点：**

- 设备扫描和过滤
- 连接状态管理
- 自动重连机制
- 连接超时处理

**实现建议：**

```dart
// Flutter 示例
class BLEConnectionManager {
  StreamSubscription<BluetoothConnectionState>? _connectionSubscription;

  Future<void> connect(BluetoothDevice device) async {
    await device.connect(
      timeout: Duration(seconds: 15),
      autoConnect: false,
    );

    _connectionSubscription = device.connectionState.listen((state) {
      if (state == BluetoothConnectionState.disconnected) {
        _handleDisconnection(device);
      }
    });
  }

  void _handleDisconnection(BluetoothDevice device) {
    // 实现自动重连逻辑
    Future.delayed(Duration(seconds: 2), () {
      device.connect();
    });
  }
}
```

class HistoryDatabase {
  static final HistoryDatabase instance = HistoryDatabase._init();
  static Database? _database;

  Future<Database> get database async {
    if (_database != null) return _database!;
    _database = await _initDB('history.db');
    return _database!;
  }

  Future<void> insertRecord(TemperatureRecord record) async {
    final db = await database;
    await db.insert('records', record.toMap());
  }

  Future<List<TemperatureRecord>> getAllRecords() async {
    final db = await database;
    final maps = await db.query('records', orderBy: 'timestamp DESC');
    return maps.map((map) => TemperatureRecord.fromMap(map)).toList();
  }
}
