# 蓝牙温湿度传输方案设计

## 1. 概述

本文档描述了 E104-BT5010A 模块通过蓝牙 BLE 传输温湿度数据的设计方案。

### 1.1 硬件平台
- **芯片**: nRF52810
- **模块**: E104-BT5010A
- **传感器**: AHT30 温湿度传感器
- **SDK**: ncs 3.2.1

### 1.2 芯片资源限制
| 资源 | 容量 | 说明 |
|------|------|------|
| RAM | 24KB | 非常有限，需谨慎使用 |
| Flash | 192KB | 包含代码和数据存储 |

## 2. 蓝牙 GATT 服务设计

### 2.1 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    E104-BT5010A 设备                        │
├─────────────────────────────────────────────────────────────┤
│  GATT Server                                                │
│  ├── Environmental Service (自定义 UUID)                    │
│  │   ├── Temperature Characteristic (可读/可通知)           │
│  │   │   └── 数据格式: int16_t (实际值×100)                │
│  │   ├── Humidity Characteristic (可读/可通知)              │
│  │   │   └── 数据格式: uint16_t (实际值×100)               │
│  │   └── Data Buffer Characteristic (可读/可通知)           │
│  │       └── 用于读取历史缓存数据                          │
│  └── Device Information Service (可选)                      │
├─────────────────────────────────────────────────────────────┤
│  数据流:                                                    │
│  AHT30 传感器 → 定时采集 → 本地缓存 → GATT 通知/读取       │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 GATT 服务定义

| 项目 | UUID | 说明 |
|------|------|------|
| **服务** | `12340001-1234-5678-1234-56789ABCDEF0` | 温湿度服务 |
| **温度特性** | `12340002-1234-5678-1234-56789ABCDEF0` | 当前温度 |
| **湿度特性** | `12340003-1234-5678-1234-56789ABCDEF0` | 当前湿度 |
| **历史数据特性** | `12340004-1234-5678-1234-56789ABCDEF0` | 缓存数据读取 |

### 2.3 数据格式

#### 温度数据
- 类型: `int16_t` (有符号16位)
- 单位: 0.01°C
- 范围: -40.00°C ~ +85.00°C
- 示例: `2350` = 23.50°C, `-500` = -5.00°C

#### 湿度数据
- 类型: `uint16_t` (无符号16位)
- 单位: 0.01%
- 范围: 0.00% ~ 100.00%
- 示例: `6500` = 65.00%

#### 历史数据包格式
```
┌──────────┬──────────┬──────────┬──────────┐
│ 时间戳   │ 温度     │ 湿度     │ 状态     │
│ 4 bytes  │ 2 bytes  │ 2 bytes  │ 1 byte   │
└──────────┴──────────┴──────────┴──────────┘
每条记录: 9 bytes
```

### 2.4 特性属性

| 特性 | Read | Write | Notify |
|------|------|-------|--------|
| 温度 | ✓ | - | ✓ |
| 湿度 | ✓ | - | ✓ |
| 历史数据 | ✓ | - | ✓ |

## 3. 本地数据缓存设计

### 3.1 存储方案对比

| 方案 | 优点 | 缺点 | 寿命 | 推荐度 |
|------|------|------|------|--------|
| **RAM 环形缓冲区** | 简单、快速、无损耗 | 断电丢失、容量有限 | 无限 | ⭐⭐⭐⭐⭐ |
| **Flash + 磨损均衡** | 断电不丢失、寿命长 | 实现复杂 | 300+ 年 | ⭐⭐⭐⭐ |
| **Flash 无均衡** | 实现简单 | 寿命短 | 4-85 年 | ⭐⭐⭐ |

**Flash 寿命说明**: 
- nRF52810 Flash 擦写次数: **10,000 次/页**
- 每次采集写入: 约 **4.3 年** (30秒间隔)
- 批量写入 (10条): 约 **43.5 年** (30秒间隔)
- 批量写入 + 8页均衡: 约 **342 年** (30秒间隔)
- 详细分析请参考: `docs/flash_lifetime_analysis.md`

### 3.2 推荐方案: RAM 环形缓冲区

考虑到 nRF52810 的资源限制，推荐使用 **RAM 环形缓冲区**：

#### 实际内存使用分析

根据编译结果，当前程序实际内存占用：

```
nRF52810 总 RAM: 24KB (24576 bytes)

当前已使用:
├── datas (已初始化):     1,648 bytes
├── device_states:           12 bytes
├── k_mem_slab_area:         84 bytes
├── k_mutex_area:            20 bytes
├── k_sem_area:              24 bytes
├── k_fifo_area:             24 bytes
├── net_buf_pool_area:      308 bytes
├── bss (未初始化):       8,412 bytes
└── noinit (栈/堆等):    10,176 bytes
─────────────────────────────────────────
已使用总计:             20,708 bytes (~20.2 KB)
剩余可用:                3,868 bytes (~3.8 KB)
```

#### 缓存容量计算

每条记录: **9 bytes** (时间戳4 + 温度2 + 湿度2 + 状态1)

| 可用空间 | 记录条数 | @30秒/次 | @60秒/次 |
|----------|----------|----------|----------|
| 2KB (保守) | **~227 条** | ~114 分钟 | ~3.8 小时 |
| 3KB (正常) | **~341 条** | ~170 分钟 | ~5.7 小时 |
| 3.5KB (激进) | **~398 条** | ~199 分钟 | ~6.6 小时 |

**推荐配置**: 使用 **2-3KB** 缓存，可存 **200-300 条记录**

#### 环形缓冲区结构
```c
// 单条温湿度记录
typedef struct {
    uint32_t timestamp;      // 系统启动后的秒数
    int16_t  temperature;    // 温度 (×100)
    uint16_t humidity;       // 湿度 (×100)
    uint8_t  status;         // 状态标志
} __packed temp_humidity_record_t;

// 环形缓冲区
#define BUFFER_SIZE 455
static temp_humidity_record_t data_buffer[BUFFER_SIZE];
static uint16_t buffer_head = 0;    // 写入位置
static uint16_t buffer_count = 0;   // 当前记录数
```

### 3.3 数据同步流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  传感器采集  │ ──> │  环形缓冲区  │ ──> │  蓝牙传输   │
└─────────────┘     └─────────────┘     └─────────────┘
      │                   │                   │
      │ 定时采集          │ 覆盖旧数据        │ 手机读取后
      │ (可配置间隔)      │ (满时)            │ 清空缓存
      ▼                   ▼                   ▼
```

### 3.4 蓝牙同步协议

#### 手机读取流程
1. 连接设备
2. 读取缓存记录数量
3. 分批读取历史数据 (每次最多 20 bytes / MTU 限制)
4. 读取完成后，发送清空指令
5. 启用实时通知

#### GATT 操作
| 操作 | 说明 |
|------|------|
| Read 历史数据特性 | 返回下一批未读数据 |
| Write 控制特性 | 0x01=清空缓存, 0x02=暂停采集 |
| Notify | 实时推送新数据 |

## 4. LED 指示设计

| 状态 | DATA LED (P0.31) | LINK LED (P0.30) |
|------|------------------|------------------|
| 初始化中 | 闪烁 (200ms) | 闪烁 (200ms) |
| 蓝牙就绪 | 熄灭 | 闪烁 (500ms) |
| 已连接 | 熄灭 | 常亮 |
| 数据发送 | 闪烁 | 常亮 |
| 缓存已满 | 快闪 (100ms) | - |
