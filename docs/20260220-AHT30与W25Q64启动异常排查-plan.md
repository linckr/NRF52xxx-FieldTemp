# 20260220 - AHT30 与 W25Q64 启动异常排查计划

## 1. 需求背景

用户贴出的启动日志中存在三类异常：

| 现象                       | 说明                                             |
| -------------------------- | ------------------------------------------------ |
| NVS 挂载失败: -45          | 内部 Flash 上的 NVS 分区挂载失败，配置使用默认值 |
| W25Q64 JEDEC ID 不匹配     | 读到的 ID 为 `0x00 0x00 0x00`，期望 `EF 40 17`   |
| AHT30 测量命令发送失败: -5 | I2C 读写持续返回 -5 (EIO)，温湿度无法采集        |

需要分析原因并给出排查/修复方案，按最小改动、先硬件后软件的原则进行。

## 2. 错误码含义（简要）

- **-5**：Zephyr 中为 `-EIO`（I/O 错误）。I2C 上常见原因：总线 NACK（从机无应答）、总线被拉死、引脚/接线错误、从机未上电或地址错误。
- **-45**：Zephyr NVS 相关错误，多与存储初始化或分区有关（具体需查 NVS 驱动返回值定义）。
- **W25Q64 全 0**：SPI 读 ID 得到 0x00 0x00 0x00 通常表示：片选/时钟/数据线接错、MISO 未接或接反、Flash 未上电、或 SPI 模式/速率不匹配。

## 3. 实现方案概述

### 3.1 定位思路（不先改业务逻辑）

1. **AHT30 -5（优先）**

   - 确认是硬件/接线问题还是软件配置问题。
   - 建议：保留现有 I2C 引脚与速率配置，先做硬件与总线排查；必要时在软件上增加 I2C 扫描结果打印、降低重复失败时的日志刷屏。

2. **W25Q64 JEDEC 全 0**

   - 确认 SPI 引脚（含 CS）、供电、MISO 连接；确认 overlay 中 SPI 与 W25Q64 节点是否与当前板子一致。
   - 可选：若为兼容多板型，可考虑在 JEDEC 读失败时降低 SPI 频率重试或增加一次复位/释放 CS 的序列后再读 ID（仍以硬件排查为主）。

3. **NVS -45**
   - 在确认 Flash 分区与 NVS 配置正确的前提下，查 NVS 返回值 -45 在 NCS/Zephyr 中的定义；若为 52832 与 52810 共用工程，需区分不同板子的分区表（如 `nrf52832dk_nrf52832_cpuapp.overlay` 与 `app.overlay` 中分区是否被正确合并）。

### 3.2 软件可做的最小改动（在硬件排查之后）

- **AHT30**

  - 若确认 I2C 硬件正常：可增加“初始化失败时不再周期性打 AHT30 失败日志”或“限频打印”，避免刷屏。
  - 可选：启动时做一次 I2C 总线扫描并打印扫描到的地址，便于确认 0x38 是否可见。

- **W25Q64**

  - 保持当前“JEDEC 不匹配仍继续、并进深度掉电”的策略，避免因外置 Flash 未接而卡死；若后续确认硬件接好仍读不到，再考虑“降速重试读 ID”或“复位 CS 后重试”等小改动。

- **NVS**
  - 查 -45 对应含义；确认当前构建使用的 overlay 与目标板（52832/52810）一致，分区起始与大小是否与 NVS 使用匹配。

## 4. 开发计划列表

- [ ] **4.1** 文档与结论：完成本排查计划文档，并给出“用户侧排查步骤”与“可选软件改动”清单。
- [ ] **4.2** AHT30：在 `main.c` 或 AHT30 调用处，当 `aht30_init()` 已失败时，避免或限频打印后续 `aht30_read()` 的 -5 错误（避免日志刷屏）。
- [ ] **4.3** AHT30（可选）：启动时若已做 I2C 扫描，确保扫描结果（是否出现 0x38）在日志中可见，便于确认硬件。
- [ ] **4.4** W25Q64：仅当硬件/接线/overlay 确认无误后仍读不到 JEDEC 时，再评估“降速或复位后重试读 ID”等小改动；否则以硬件排查为主。
- [ ] **4.5** NVS：查 NCS 3.2.1 中 NVS 返回 -45 的含义，并核对当前使用的 overlay 分区与目标板一致。

## 5. 用户侧建议排查步骤（先做再改代码）

1. **AHT30（-5）**

   - 确认 AHT30 模块已正确接到 I2C 总线（SDA→P0.7, SCL→P0.6，与 overlay 一致）。
   - 确认模块供电（VCC/GND）及 I2C 上拉电阻（板载或模块自带 4.7k/2.2k）。
   - 用万用表/逻辑分析仪看 SDA/SCL 是否有波形、是否有 NACK。
   - 若有可能，用其他主机或工具扫描 I2C 总线，看 0x38 是否应答。

2. **W25Q64（JEDEC 0x00 0x00 0x00）**

   - 确认 CS(P0.28)、SCK(P0.30)、MOSI(P0.31)、MISO(P0.29)、VCC/GND 连接与 overlay 一致。
   - 确认 W25Q64 供电电压与电平匹配。
   - 重点确认 MISO 是否接到 MCU 的 MISO 引脚（读 ID 全 0 常为 MISO 未接或接错）。

3. **NVS（-45）**
   - 确认烧录/运行的是否为 52832 镜像，使用的 overlay 是否为 `nrf52832dk_nrf52832_cpuapp.overlay`（与 app.overlay 合并后分区是否含 `nvs_storage` 且大小正确）。

## 6. 小结

- **AHT30 -5**：先按 I2C 硬件与接线排查；软件上可做“初始化失败后限频/不再刷屏 AHT30 失败日志”及“打印 I2C 扫描结果”。
- **W25Q64 全 0**：以 SPI 与电源接线、MISO 为重点做硬件排查；软件保持当前容错行为，必要时再考虑降速/重试读 ID。
- **NVS -45**：查错误码定义并核对分区与板型一致后再决定是否改配置或代码。

完成 4.1 后，可根据用户确认再实施 4.2、4.3 等可选软件改动。
