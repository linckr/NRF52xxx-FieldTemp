# 开发阶段时钟配置指南

## 1. 概述

本文档说明在开发阶段（无外部晶振）和量产阶段（有外部晶振）的时钟配置方法，以及如何平滑过渡。

---

## 2. 当前配置（开发阶段 - 使用内部 RC）

### 2.1 当前配置状态

**prj.conf 配置：**

```conf
# 时钟配置
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y      # 使用内部 RC 振荡器
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=n    # 禁用外部晶振
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=y  # 启用500ppm校准
```

### 2.2 内部 RC 的优势（开发阶段）

| 优势 | 说明 |
|------|------|
| **无需硬件** | 不需要外部晶振和负载电容 |
| **快速启动** | 启动时间 < 1ms，不会卡死 |
| **成本低** | 零额外成本 |
| **开发便利** | 适合开发和调试阶段 |

### 2.3 内部 RC 的劣势

| 劣势 | 说明 |
|------|------|
| **功耗较高** | 需要周期性校准，增加约 8-11 μA 功耗 |
| **精度低** | ±500 ppm，时间精度较差 |
| **频率不稳定** | 受温度影响大，BLE连接窗口需要更长 |

### 2.4 开发阶段注意事项

**代码中已有说明：**

```c
/*
 * 重要配置说明：
 * - 时钟配置：E104-BT5010A 模块没有外部晶振，必须使用内部 RC 振荡器
 *   在 prj.conf 中已配置：
 *   CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y  (使用内部 RC 作为 32kHz 时钟源)
 *   这确保系统不会因等待外部晶振起振而卡死
 */
```

**关键点：**
- ✅ 开发阶段可以直接使用内部 RC，无需任何硬件改动
- ✅ 系统会自动使用内部 RC，不会等待外部晶振
- ✅ 所有功能都可以正常开发和测试

## 3. 量产阶段配置（使用外部晶振）

### 3.1 硬件准备

需要准备的元器件：

| 元器件 | 规格 | 数量 |
|--------|------|------|
| **32.768kHz 无源晶振** | 3225, CL=12.5pF, ±10ppm/20ppm | 1 |
| **负载电容** | 22pF ±5%, C0G, 0402/0603 | 2 |

### 3.2 软件配置修改

**prj.conf 配置（量产阶段）：**

```conf
# 时钟配置（量产阶段 - 使用外部晶振）
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=y    # 启用外部晶振
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=n      # 禁用内部RC
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=n  # 不需要500ppm校准
```

### 3.3 配置切换步骤

1. **硬件焊接**：在 PCB 上焊接晶振和负载电容
2. **修改配置**：修改 `prj.conf` 中的时钟配置
3. **重新编译**：清理并重新编译项目
4. **烧录测试**：烧录并验证系统正常工作

## 4. 平滑过渡方案

### 4.1 方案一：使用 Kconfig 条件编译（推荐）

可以通过 Kconfig 选择在开发阶段或量产阶段使用不同的配置。

**prj.conf（开发阶段）：**

```conf
# 开发阶段：使用内部 RC
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=n
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=y
```

**prj.conf（量产阶段）：**

```conf
# 量产阶段：使用外部晶振
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=y
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=n
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=n
```

### 4.2 方案二：使用配置文件切换

可以创建两个配置文件：

**prj.conf.development**（开发阶段配置）：

```conf
# 开发阶段：使用内部 RC
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=n
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=y
```

**prj.conf.production**（量产阶段配置）：

```conf
# 量产阶段：使用外部晶振
CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL=y
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=n
CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM=n
```

**编译时指定配置：**

```bash
# 开发阶段编译
cp prj.conf.development prj.conf
west build -b e104_bt5010a_tb

# 量产阶段编译
cp prj.conf.production prj.conf
west build -b e104_bt5010a_tb
```

### 4.3 方案三：使用 CMake 变量

可以在 `CMakeLists.txt` 中定义变量：

```cmake
# CMakeLists.txt
if(USE_CRYSTAL)
    set(CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL y)
    set(CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC n)
else()
    set(CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL n)
    set(CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC y)
endif()
```

**编译时指定：**

```bash
# 开发阶段（默认）
west build -b e104_bt5010a_tb

# 量产阶段（使用外部晶振）
west build -b e104_bt5010a_tb -- -DUSE_CRYSTAL=1
```

## 6. 常见问题

### 6.1 Q: 开发阶段使用内部RC，会影响功能测试吗？

**A:** 不会。所有功能都可以正常开发和测试，只是：
- 功耗稍高（约 11 μA）
- 时间精度稍差（±500 ppm）
- BLE连接可能需要稍长时间（但功能正常）

### 6.2 Q: 开发阶段测试的代码，量产时还需要修改吗？

**A:** 通常不需要。只需要修改 `prj.conf` 中的时钟配置即可，代码逻辑无需改动。

### 6.3 Q: 如果量产时忘记修改配置，会怎样？

**A:** 如果配置为外部晶振但硬件没有晶振，系统会：
- 尝试等待外部晶振起振
- 可能卡死在等待状态（取决于配置）
- 建议：量产前务必验证配置和硬件是否匹配

### 6.4 Q: 可以在有晶振的板子上开发，但代码支持无晶振吗？

**A:** 可以。Zephyr 支持运行时检测，但推荐使用配置开关（Kconfig）来明确指定。

### 6.5 Q: 开发阶段需要模拟外部晶振的行为吗？

**A:** 不需要。内部 RC 已经可以满足所有开发需求，无需额外模拟。

## 7. 最佳实践

### 7.1 开发阶段建议

1. **直接使用内部 RC**：无需任何硬件改动，快速开发
2. **保留 UART 调试**：开发阶段保留串口输出，便于调试
3. **记录功耗数据**：记录开发阶段的功耗数据，与量产阶段对比

### 7.2 量产准备建议

1. **提前测试外部晶振**：在样品阶段测试外部晶振配置
2. **验证功耗**：对比开发阶段和量产阶段的功耗差异
3. **时间精度测试**：验证外部晶振的时间精度是否符合要求

### 7.3 配置管理建议

1. **使用版本控制**：将不同阶段的配置文件纳入版本控制
2. **文档化配置**：在代码注释中说明当前配置和切换方法
3. **编译脚本**：可以编写脚本自动切换配置文件

## 8. 配置切换清单

### 8.1 开发阶段 → 量产阶段

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1. **硬件准备** | 焊接晶振和负载电容 | 参考《32.768kHz晶振选型与功耗分析.md》 |
| 2. **修改配置** | 修改 `prj.conf` | 启用 XTAL，禁用 RC |
| 3. **更新注释** | 更新代码注释 | 说明当前使用外部晶振 |
| 4. **清理编译** | `west build -t clean` | 清理之前的编译 |
| 5. **重新编译** | `west build -b e104_bt5010a_tb` | 使用新配置编译 |
| 6. **烧录测试** | 烧录并测试 | 验证功能正常 |
| 7. **功耗测试** | 测量实际功耗 | 对比理论值和实际值 |
| 8. **时间精度测试** | 测试时间精度 | 验证是否符合要求 |

### 8.2 量产阶段 → 开发阶段（回退）

如果需要回退到开发配置：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1. **修改配置** | 修改 `prj.conf` | 启用 RC，禁用 XTAL |
| 2. **重新编译** | `west build -b e104_bt5010a_tb` | 使用RC配置编译 |
| 3. **烧录测试** | 烧录并测试 | 验证功能正常 |

**注意：** 即使硬件有晶振，使用内部RC配置也能正常工作（晶振会被忽略）。
