# 离线时间机制：候选 1.0.12 / App 1.1.5

本轮参考用户提供的“相对时间记录＋连接后反向校准＋断电会话标识”方案。以下是当前实现，不代表已经完成新固件真机验收。旧骑行记录未修改。

## 时间与会话

- 启动时不再把 NVS 上次保存的 Unix 时间当成本次真实时间。未校时也可以采样、聚合并保存历史。
- `boot_base` 是本次启动独有的递增会话基点。NVS key 8 原子保存编号高水位及最近一次首次校时锚点，带版本 magic 与载荷校验；不更改现有分区、旧 key 或 12 B 记录布局。
- 未校时记录的 timestamp 是 `boot_base + uptime_seconds`，为不透明相对编号，范围 `1..946684799`，不能显示成 1970 年日期。每次启动先持久化保留 3600 秒编号空间，超出时先保留下一段再使用。重启从已经保留的高水位之后继续，编号不重复；长时间离线仍可扩展。
- 编号空间有限，约 30 年累计保留秒数，每次启动至少消耗一小时编号。元数据损坏、空间耗尽或保留失败时拒绝产生未获保留的相对编号，不静默回到旧日期。OTA 活跃期间不扩展编号、不写时间锚点。
- 首次手机对时保存 `(boot_base, uptime_at_sync_s, utc_at_sync_s)`。此前属于同一基点范围的记录按 `UTC = raw_id - boot_base + utc_at_sync - uptime_at_sync` 重建；锚点一旦保存，本次启动后续对时不修改该锚点。
- NVS 保留最近一次首次锚点，即使对时完成后 App 尚未读取就掉电，也可以在下次连接先取回。App 在写入新锚点前先保存旧锚点，再读回新锚点，Room 保留已取得的映射。
- 本 MVP 不在模块上保存无限多会话锚点。未取得锚点便结束的旧会话只保留相对编号和记录，不推断断电时长；未配套的新旧客户端混用可能使尚未取走的旧锚点被替换，此类记录仍按未知时间保留。不同手机只拥有各自已取得的映射，不能声称任意手机均能还原全部旧会话。
- 不批量重写 NOR 历史扇区。校正发生在 App 入库/已有未定时行解释阶段，温湿度、气压、电压和原始编号保留。不能用条数乘间隔恢复旧记录，因为存在事件记录和部分窗口。

## BLE 兼容

UUID、历史 12/14 B 布局、4 B Unix 秒写入保持不变。

时间特征 `12340011` 在 v12 增加 READ，返回 24 B 小端元数据：

| offset | 类型 | 内容 |
|---|---|---|
| 0 | uint32 | `0x31434c4f`，ASCII OLC1 |
| 4 | uint32 | 当前 boot_base，0 表示分配失败 |
| 8 | uint32 | 最近一次锚点所属 boot_base，0 表示尚无锚点 |
| 12 | uint32 | 锚点 Unix 秒 |
| 16 | uint32 | 锚点 uptime 秒 |
| 20 | uint32 | 已持久化的编号高水位 |

历史显式请求 `[timestamp LE32][0x05]` 选择 14 B 并允许相对编号。v12 App 在版本匹配且请求 ACK 成功后使用该语义；原 `[timestamp][0x03]` 和 4 B 请求不发送相对记录，避免旧客户端误显示日期。断连清除协商状态。

0x05 请求从逻辑最旧位置线性扫描；可信 Unix 记录继续应用增量时间过滤，相对编号记录不受 Unix 过滤，重复接收按原始编号更新同一行。不能对混合时间域执行按日期二分定位。容量与记录顺序不变。

## App 与数据库

- Room 11→12 为旧行新增 `rawTimestamp=NULL`、`timeUncertain=0`，新增会话锚点表；不猜测旧记录属于哪个会话，不重写旧骑行日期。
- 未知记录显示“时间未确定”；反向校准行保留 rawTimestamp 并标记“已校准”；正常校时后记录按原 Unix 时间显示。可信度区分 SYNCED / RECONSTRUCTED / UNKNOWN，本轮不自动生成 ESTIMATED。
- 校准前后及反复下载，以设备＋rawTimestamp 保持相对记录身份和 ID；普通旧记录仍使用原有去重路径。手机采样、GPS 和其他未校时会话不能被锚点更新。
- 未知记录不进入正常日期曲线；无日期筛选的历史列表和 CSV 保留它们，导出携带原始编号和时间状态。
- 本地历史设备选择在蓝牙准备之外初始化，地址就绪后重载列表与曲线。蓝牙关闭或没有权限时，启动不强制弹出连接准备；手动连接仍走权限流程。

## 精度与待验收

继续使用兼容的秒级手机对时；截断、链路延迟和设备时钟漂移都会影响重建精度，不能将 RECONSTRUCTED 宣称为精确测量时刻。未校时周期按 uptime 推进，首次对时后才恢复墙钟边界对齐。

真实设备仍须验证：无既有时间的首次启动、数小时离线后首次连接、未校时多次掉电、对时 ACK 后立即掉电、跨启动旧锚点取回、编号扩展、已有历史无损迁移。当前设备保留 1.0.11，不能将主机故障夹具或 App 测试当作上述硬件验证。

## 恢复与冲突边界

编号唯一性依赖 NVS key 8 的高水位持续保留。不得在保留新历史或手机映射的同时单独清空、回滚该 key；工厂恢复须同时规划历史和手机会话映射的隔离。校验和不能识别一个内容完整但过旧的 NVS 备份。

App 拒绝与已存锚点不一致的会话映射，也拒绝以相同相对编号覆盖不同传感器内容；元数据验证未完成时不启动 v12 历史下载。这是保全数据的冲突保护，并不等于能识别任意工厂回滚。旧行迁移默认值只保证保留原样，不证明旧日期可信。
