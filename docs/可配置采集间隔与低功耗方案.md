# 可配置采集间隔与低功耗优化方案

## 1. 方案概述

### 1.1 需求

- **手机可配置采集间隔**: 通过蓝牙 GATT 服务，手机可以动态修改温湿度记录时间间隔（例如：10 秒、30 秒、60 秒、300 秒等）
- **低功耗优化**: 在采集间隔期间，系统进入深度睡眠模式，大幅降低功耗
- **目标续航**: 从当前的 15 小时提升到 **30-90 天**（取决于采集间隔）

### 1.2 硬件平台

- **芯片**: nRF52810
- **模块**: E104-BT5010A
- **传感器**: AHT30 温湿度传感器
- **SDK**: ncs 3.2.1
- **电池**: CR2032 (220mAh)

## 3. GATT 服务设计

### 3.1 配置服务（新增）

| 项目             | UUID                                   | 说明                                          |
| ---------------- | -------------------------------------- | --------------------------------------------- |
| **服务**         | `12340020-1234-5678-1234-56789ABCDEF0` | 配置服务                                      |
| **采集间隔特性** | `12340021-1234-5678-1234-56789ABCDEF0` | 可读/可写，单位：秒                           |
| **当前状态特性** | `12340022-1234-5678-1234-56789ABCDEF0` | 可读/可通知，包含：采集间隔、记录数、系统状态 |

#### 采集间隔特性

- **数据类型**: `uint16_t` (2 bytes)
- **单位**: 秒
- **范围**: 10 ~ 3600 秒（10 秒 ~ 1 小时）
- **默认值**: 30 秒
- **权限**: Read + Write
- **写入后**: 立即生效，更新 RTC 定时器

#### 当前状态特性

- **数据格式**:
  ```
  ┌──────────┬──────────┬──────────┬──────────┐
  │ 采集间隔  │ 记录数   │ 系统状态 │ 保留     │
  │ 2 bytes  │ 2 bytes  │ 1 byte   │ 1 byte   │
  └──────────┴──────────┴──────────┴──────────┘
  总计: 6 bytes
  ```
- **权限**: Read + Notify
- **通知触发**: 采集间隔改变、记录数变化、系统状态变化

### 3.2 数据服务（已有，需扩展）

保持现有的温湿度服务，添加历史数据读取功能。

## 4. 低功耗实现方案

### 4.1 功耗优化策略

| 优化项         | 当前状态         | 优化后                   | 功耗降低   |
| -------------- | ---------------- | ------------------------ | ---------- |
| **主循环睡眠** | 1 秒唤醒         | 按采集间隔（10-3600 秒） | **99%+**   |
| **蓝牙广播**   | 快速广播 (100ms) | 慢速广播 (2-5 秒)        | **80-90%** |

| **I2C 总线** | 保持激活 | 读取后关闭 | **10-20%** |
| **MCU 模式** | 全速运行 | System ON 睡眠 | **99%+** |

目前开发环境，不需要，正式时候才屏蔽
| **LED 闪烁** | 持续闪烁 | 仅关键事件闪烁 | **90%+** |
| **UART 输出** | 持续打印 | 关闭或条件编译 | **50-100%** |

### 4.2 睡眠模式选择

#### System ON 模式（推荐）

- **功耗**: 1-2 μA（睡眠时）
- **唤醒方式**: RTC 定时器、蓝牙中断
- **RAM 保持**: ✓（数据不丢失）
- **唤醒时间**: < 1ms
- **适用场景**: 需要保持蓝牙连接、需要快速响应

#### System OFF 模式（不推荐）

- **功耗**: 0.4-1.5 μA（最低）
- **唤醒方式**: 仅外部中断（蓝牙无法唤醒）
- **RAM 保持**: ✗（数据丢失）
- **唤醒时间**: 较长（需要重新初始化）
- **适用场景**: 完全不需要蓝牙时

**结论**: 使用 **System ON 模式**，通过 RTC 定时器唤醒。

### 4.3 RTC 定时器配置

```c
// 使用 nRF52810 的 RTC0 作为定时器
// 配置为 32.768kHz 时钟源（内部 RC 或外部晶振）

// 定时器结构
struct k_timer sample_timer;

// 定时器回调
void sample_timer_handler(struct k_timer *timer)
{
    // 唤醒系统，触发采集任务
    k_work_submit(&sample_work);
}

// 配置定时器
k_timer_init(&sample_timer, sample_timer_handler, NULL);
k_timer_start(&sample_timer, K_SECONDS(sample_interval), K_NO_WAIT);
```

### 4.4 主循环优化

```c
int main(void)
{
    // 初始化...

    while (1) {
        // 1. 采集温湿度
        aht30_read(&temperature, &humidity);

        // 2. 存储数据
        buffer_add_record(timestamp, temperature, humidity);

        // 3. 更新 GATT 特性
        update_gatt_characteristics();

        // 4. 发送通知（如果已连接）
        if (bt_connected && notify_enabled) {
            bt_gatt_notify(...);
        }

        // 5. 进入低功耗模式
        // k_sleep() 会自动让系统进入 System ON 模式
        k_sleep(K_SECONDS(sample_interval));

        // 6. 唤醒后继续循环
    }
}
```

### 4.5 蓝牙广播优化

```c
// 初始 30 秒：快速广播（便于发现）
bt_le_adv_start(BT_LE_ADV_CONN_FAST_1, ad, ARRAY_SIZE(ad), NULL, 0);

// 30 秒后：切换到慢速广播（降低功耗）
k_work_schedule(&adv_slow_work, K_SECONDS(30));

// 慢速广播回调
void adv_slow_work_handler(struct k_work *work)
{
    bt_le_adv_stop();
    // 使用自定义参数：间隔 2-5 秒
    struct bt_le_adv_param param = {
        .options = BT_LE_ADV_OPT_CONNECTABLE,
        .interval_min = BT_GAP_ADV_FAST_INT_MIN_2,  // 2秒
        .interval_max = BT_GAP_ADV_FAST_INT_MAX_2,  // 5秒
    };
    bt_le_adv_start(&param, ad, ARRAY_SIZE(ad), NULL, 0);
}
```

## 5. 配置持久化

### 5.1 存储方案

由于 nRF52810 Flash 寿命有限，建议使用 **Settings 子系统**（Zephyr 自带）或简单的 Flash 存储。

#### 方案一：Settings 子系统（推荐）

- **优点**: 自动管理 Flash 磨损均衡
- **缺点**: 需要额外配置
- **实现**: 使用 `CONFIG_SETTINGS=y`

#### 方案二：简单 Flash 存储

- **优点**: 实现简单，内存占用小
- **缺点**: 需要手动管理磨损
- **实现**: 使用 `flash_write()` API

### 5.2 配置数据结构

```c
// 配置结构（存储在 Flash）
typedef struct {
    uint16_t sample_interval;  // 采集间隔（秒）
    uint8_t  reserved[2];      // 保留
} __packed device_config_t;

// 默认配置
#define DEFAULT_SAMPLE_INTERVAL  30  // 30秒

// 配置存储地址（Flash 末尾，避免与代码冲突）
#define CONFIG_FLASH_ADDR  0x00030000  // 示例地址
```

### 5.3 配置读取/写入流程

```c
// 启动时读取配置
static void load_config(void)
{
    device_config_t config;
    int ret = flash_read(...);
    if (ret == 0 && config.sample_interval >= 10 && config.sample_interval <= 3600) {
        sample_interval = config.sample_interval;
    } else {
        sample_interval = DEFAULT_SAMPLE_INTERVAL;  // 使用默认值
    }
}

// 配置改变时保存
static void save_config(void)
{
    device_config_t config = {
        .sample_interval = sample_interval,
    };
    flash_write(CONFIG_FLASH_ADDR, &config, sizeof(config));
}
```

## 6. 功耗计算与续航预估

### 6.1 功耗模型

#### 睡眠期间（占大部分时间）

| 组件           | 功耗         | 说明         |
| -------------- | ------------ | ------------ |
| System ON 睡眠 | 1-2 μA       | MCU 深度睡眠 |
| RTC 定时器     | 0.5-1 μA     | 保持计时     |
| **小计**       | **1.5-3 μA** | 睡眠期间     |

#### 唤醒期间（短暂）

| 组件           | 功耗       | 持续时间   | 说明       |
| -------------- | ---------- | ---------- | ---------- |
| MCU 运行       | 4-5 mA     | 100-200ms  | 采集和处理 |
| I2C 通信       | 1-2 mA     | 80ms       | AHT30 读取 |
| 蓝牙（如连接） | 0.5-2 mA   | 50ms       | 发送通知   |
| **小计**       | **5-9 mA** | **~300ms** | 每次采集   |

#### 蓝牙广播期间

| 模式     | 功耗       | 说明     |
| -------- | ---------- | -------- |
| 快速广播 | 5-8 mA     | 前 30 秒 |
| 慢速广播 | 0.1-0.3 mA | 之后     |

### 6.2 平均功耗计算

#### 场景一：采集间隔 = 30 秒，未连接

```
睡眠时间: 29.7秒 (99%)
唤醒时间: 0.3秒 (1%)

平均功耗 = (1.5μA × 29.7s + 6mA × 0.3s) / 30s
         = (0.0445mAs + 1.8mAs) / 30s
         = 0.0615 mA ≈ 0.06 mA
```

#### 场景二：采集间隔 = 60 秒，未连接

```
平均功耗 ≈ 0.03 mA
```

#### 场景三：采集间隔 = 300 秒（5 分钟），未连接

```
平均功耗 ≈ 0.006 mA
```

### 6.3 续航时间预估

**电池容量**: 220 mAh (CR2032)

| 采集间隔 | 平均功耗 | 续航时间                 | 说明     |
| -------- | -------- | ------------------------ | -------- |
| 10 秒    | 0.18 mA  | **1222 小时** (51 天)    | 高频采集 |
| 30 秒    | 0.06 mA  | **3667 小时** (153 天)   | 推荐配置 |
| 60 秒    | 0.03 mA  | **7333 小时** (305 天)   | 低频采集 |
| 300 秒   | 0.006 mA | **36667 小时** (1528 天) | 极低频   |

**注意**: 实际续航会受到蓝牙连接、LED 使用等因素影响。

## 7. 代码实现要点

### 7.1 关键配置（prj.conf）

```conf
# 电源管理（必需）
CONFIG_PM=y
CONFIG_PM_DEVICE=y

# RTC 定时器（必需）
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y  # 使用内部 RC（已有）

# DCDC 转换器（降低功耗）
CONFIG_BOARD_ENABLE_DCDC=y

# 可选：关闭 UART 以降低功耗（生产环境）
# CONFIG_SERIAL=n
# CONFIG_CONSOLE=n
```

### 7.2 关键代码结构

```c
// 全局变量
static uint16_t sample_interval = 30;  // 采集间隔（秒）
static struct k_timer sample_timer;    // 采集定时器
static struct k_work sample_work;      // 采集工作队列

// 采集定时器回调
void sample_timer_handler(struct k_timer *timer)
{
    k_work_submit(&sample_work);
}

// 采集工作函数
void sample_work_handler(struct k_work *work)
{
    int32_t temperature, humidity;

    // 读取传感器
    aht30_read(&temperature, &humidity);

    // 存储数据
    buffer_add_record(get_current_timestamp(), temperature, humidity);

    // 更新 GATT
    update_gatt_characteristics(temperature, humidity);

    // 发送通知
    if (bt_connected) {
        bt_gatt_notify(...);
    }

    // 设置下次唤醒
    k_timer_start(&sample_timer, K_SECONDS(sample_interval), K_NO_WAIT);
}

// 配置写入回调（GATT）
static ssize_t interval_char_write_cb(...)
{
    uint16_t new_interval = sys_get_le16(buf);

    // 验证范围
    if (new_interval < 10 || new_interval > 3600) {
        return BT_GATT_ERR(BT_ATT_ERR_VALUE_NOT_ALLOWED);
    }

    // 更新配置
    sample_interval = new_interval;

    // 保存到 Flash
    save_config();

    // 重启定时器
    k_timer_stop(&sample_timer);
    k_timer_start(&sample_timer, K_SECONDS(sample_interval), K_NO_WAIT);

    return len;
}

// 主循环
int main(void)
{
    // 初始化...

    // 加载配置
    load_config();

    // 初始化定时器
    k_timer_init(&sample_timer, sample_timer_handler, NULL);
    k_work_init(&sample_work, sample_work_handler);

    // 启动第一次采集
    k_work_submit(&sample_work);

    // 主循环：进入低功耗
    while (1) {
        // k_sleep() 会让系统进入 System ON 模式
        // 定时器唤醒后会触发工作队列，然后继续睡眠
        k_sleep(K_FOREVER);  // 永久睡眠，等待定时器唤醒
    }
}
```

## 9. 功耗测试方法（RF CONNECT）

### 9.1 RF CONNECT 工具介绍

**RF CONNECT**（也称为 **Power Profiler**）是 Nordic 官方提供的功耗测试工具，用于精确测量 nRF 系列芯片的实时功耗。

#### 工具特点

- **高精度**: 可测量 μA 级别的电流
- **实时显示**: 实时功耗曲线和统计数据
- **时间降额**: 支持长时间测试的降额功能
- **多模式**: 支持平均功耗、峰值功耗、能量统计等

### 9.2 测试连接方法

#### 硬件连接

```
┌─────────────┐         ┌──────────────┐         ┌─────────────┐
│  E104-BT    │         │  RF CONNECT  │         │   电源/电池  │
│  BT5010A    │────────>│  Power      │────────>│             │
│  设备       │  VDD    │  Profiler   │  VDD    │             │
└─────────────┘         └──────────────┘         └─────────────┘
```

**连接步骤**:

1. 断开设备电源（移除电池或断开电源线）
2. 将 RF CONNECT 的 **VDD** 输出连接到设备的 **VDD** 引脚
3. 将 RF CONNECT 的 **GND** 连接到设备的 **GND** 引脚
4. 确保 RF CONNECT 通过 USB 连接到电脑
5. 在 RF CONNECT 软件中设置输出电压（通常为 **3.0V**，匹配 CR2032 电池电压）

### 9.3 RF CONNECT 软件配置

#### 基本设置

1. **打开 RF CONNECT 软件**
2. **选择设备**: 选择连接的 Power Profiler 设备
3. **设置电压**: 设置为 **3.0V**（匹配 CR2032 电池电压）
4. **设置电流范围**:
   - 睡眠期间：选择 **μA 范围**（例如 0-100 μA）
   - 唤醒期间：选择 **mA 范围**（例如 0-10 mA）
   - 或使用 **自动范围**

#### 测试模式选择

| 模式         | 说明             | 适用场景           |
| ------------ | ---------------- | ------------------ |
| **实时模式** | 实时显示功耗曲线 | 观察功耗变化、调试 |
| **平均模式** | 计算平均功耗     | 验证理论计算值     |
| **能量模式** | 计算总能量消耗   | 评估电池续航       |

### 9.4 时间降额（Time Derating）配置

#### 什么是时间降额？

**时间降额**（Time Derating）是 RF CONNECT 的一个功能，用于处理**长时间测试**的情况。当测试时间过长时，可以通过降额功能来**加速测试**，同时保持测试结果的准确性。

#### 为什么需要时间降额？

- **测试时间过长**: 例如测试 30 秒采集间隔的功耗，需要等待多个周期才能获得准确的平均值
- **提高效率**: 通过降额可以缩短实际测试时间
- **保持准确性**: 降额算法确保测试结果仍然准确

#### 如何设置时间降额？

##### 方法一：通过软件界面设置

1. **打开 RF CONNECT 软件**
2. **进入设置菜单**: 点击右上角的 **设置图标**（齿轮图标）
3. **找到 "Time Derating" 选项**:
   - 位置：`Settings` → `Measurement` → `Time Derating`
4. **设置降额参数**:
   - **Derating Factor（降额因子）**: 例如设置为 **10** 或 **100**
     - `10`: 实际测试 1 秒，相当于测试 10 秒
     - `100`: 实际测试 1 秒，相当于测试 100 秒
   - **Derating Mode（降额模式）**:
     - `Linear`: 线性降额（推荐）
     - `Exponential`: 指数降额

##### 方法二：通过配置文件设置

如果软件支持，可以在配置文件中设置：

```json
{
  "measurement": {
    "time_derating": {
      "enabled": true,
      "factor": 100,
      "mode": "linear"
    }
  }
}
```

#### 时间降额计算示例

假设设备采集间隔为 **30 秒**，需要测试 **10 个周期**（300 秒）：

### 9.7 常见问题

#### Q1: 时间降额在哪里设置？

**A**: 在 RF CONNECT 软件的设置菜单中：

- `Settings` → `Measurement` → `Time Derating`
- 或通过配置文件设置

#### Q2: 降额因子设置多少合适？

**A**:

- 短间隔（< 30 秒）：可以不使用降额或使用因子 10
- 长间隔（> 60 秒）：建议使用因子 10-50
- 极长间隔（> 300 秒）：可以使用因子 50-100

#### Q3: 降额会影响测试精度吗？

**A**:

- 降额因子 < 50：影响很小，可以忽略
- 降额因子 50-100：可能有轻微影响，但仍在可接受范围
- 降额因子 > 100：不推荐，可能影响精度

#### Q4: 如何验证降额后的结果准确性？

**A**:

1. 先不使用降额测试一次（作为基准）
2. 再使用降额测试一次
3. 对比两次结果，误差应在 **5%** 以内

## 10. 注意事项

### 10.1 蓝牙连接时的功耗

- 已连接时，系统需要保持蓝牙栈运行
- 功耗会增加到 **1-2 mA**（取决于连接间隔）
- 建议：连接时适当缩短采集间隔，断开后恢复

### 10.2 Flash 寿命

- 配置写入频率低（仅在用户修改时）
- 使用磨损均衡或简单存储方案
- 预计寿命：**10+ 年**（假设每天修改一次）

### 10.3 唤醒延迟

- RTC 定时器精度：±500ppm（内部 RC）
- 实际误差：约 **±0.05%**（30 秒间隔误差约 ±15ms）
- 可接受范围

### 10.4 调试建议

- 开发阶段保留 UART 输出
- 生产环境关闭 UART 以降低功耗
- 使用条件编译控制调试输出
