# NVS 挂载与分区调整总结

**日期**：2026-02-20

本文档总结本次对 NVS（Non-Volatile Storage）的修改：修复 52832 上挂载失败 -45，以及将分区从 20KB 调整为 12KB。

---

## 1. 问题与原因

### 1.1 现象

- 在 nRF52832 上启动时出现：`[NVS] 挂载失败: -45`

### 1.2 原因

- 错误码 **-45** 为 **EIO（I/O 错误）**，表示对 Flash 的访问失败。
- 代码中曾将 NVS 分区**起始地址和大小**写死为 52810 的布局（`0x2A000`，20KB）。
- nRF52832 的 board overlay 中 NVS 分区实际在 **0x78000**，大小 20KB。
- 为 52832 编译时，代码仍按 0x2A000 访问，导致访问错误地址，触发 -45。

| 板型                  | NVS 分区起始 | 说明           |
| --------------------- | ------------ | -------------- |
| 52810 (app.overlay)   | 0x2A000      | 原硬编码值     |
| 52832 (board overlay) | 0x78000      | 实际生效的 DTS |

---

## 2. 修改一：用 DTS 分区替代硬编码

### 2.1 思路

- 分区 offset/size 不再在代码中写死，改为从设备树中读取。
- 编译时根据所用 overlay 自动得到对应板型的 NVS 分区，52810 与 52832 共用同一套代码。

### 2.2 涉及文件与改动

**`src/storage/nvs_config.h`**

- 删除硬编码宏：`NVS_PARTITION_OFFSET`、`NVS_PARTITION_SIZE`、`NVS_SECTOR_COUNT`。
- 保留：`NVS_SECTOR_SIZE = 4096`（单扇区 4KB，与 NVS 及 Flash 页对齐）。

**`src/storage/nvs_config.c`**

- 使用 **SoC 编译期回退** 确定 NVS 分区 offset/size，避免 DTS overlay 合并顺序或 PM 导致 52832 误用 52810 的 0x2A000 而继续 -45：
  - `CONFIG_SOC_NRF52832` 时：offset=0x78000，size=12KB；
  - 否则（52810 等）：offset=0x2A000，size=12KB。
- 挂载失败时 printk 会打印当前使用的 offset/size，便于排查。
- **说明**：曾尝试用 `FIXED_PARTITION_*`（依赖 Nordic PM，未定义）和 `DT_REG_* (DT_NODELABEL(nvs_partition))`（在部分构建下仍可能取到错误分区），最终改为按 SoC 写死与 overlay 一致的值，保证 52832 一定用 0x78000。

效果：52832 使用 0x78000、52810 使用 0x2A000，均由 DTS 决定，挂载 -45 问题消除。

---

## 3. 修改二：NVS 分区大小核算与改为 12KB

### 3.1 实际占用估算

当前 NVS 存 5 个 key：

| Key                  | 内容            | 数据长度 | 单条占用（8B 头 + 数据） |
| -------------------- | --------------- | -------- | ------------------------ |
| NVS_ID_NEXT_SECTOR   | uint16_t        | 2 B      | 10 B                     |
| NVS_ID_OLDEST_SECTOR | uint16_t        | 2 B      | 10 B                     |
| NVS_ID_NEXT_RECORD   | uint16_t        | 2 B      | 10 B                     |
| NVS_ID_CONFIG        | device_config_t | 16 B     | 24 B                     |
| NVS_ID_TIME_BASE     | uint32_t        | 4 B      | 12 B                     |
| **合计**             |                 | **26 B** | **66 B**                 |

- Zephyr NVS 每条记录有 8 字节元数据（ATE）。
- 逻辑上“一套”数据约 66 字节，NVS 需要至少 2 个 sector（8KB）才能正常磨损均衡。
- 12KB（3×4KB sector）足够当前用途，且留有余量。

### 3.2 分区由 20KB 改为 12KB

**`boards/nrf52832dk_nrf52832_cpuapp.overlay`**

- NVS 分区 `reg`：由 `<0x00078000 0x00005000>` 改为 `<0x00078000 0x00003000>`。
- 即：起始仍为 0x78000，大小由 20KB 改为 12KB（0x78000–0x7B000）。

**`app.overlay`**

- NVS 分区 `reg`：由 `<0x0002A000 0x00005000>` 改为 `<0x0002A000 0x00003000>`。
- 即：起始仍为 0x2A000，大小由 20KB 改为 12KB（0x2A000–0x2D000）。

`nvs_config.c` 中已使用 `FIXED_PARTITION_SIZE(nvs_partition) / NVS_SECTOR_SIZE`，分区改为 12KB 后会自动得到 3 个 sector，无需改代码。

---

## 4. 修改汇总

| 项目                 | 修改前                        | 修改后                                     |
| -------------------- | ----------------------------- | ------------------------------------------ |
| NVS 分区 offset/size | 头文件中硬编码 0x2A000 / 20KB | 从 DTS 读取（FIXED_PARTITION_OFFSET/SIZE） |
| NVS 分区总大小       | 20KB（两 overlay）            | 12KB（两 overlay）                         |
| NVS sector 数        | 5（20KB/4KB）                 | 3（12KB/4KB），由 DTS 计算                 |

---

## 5. 注意事项

- 若设备上曾以 20KB 分区写过 NVS，改为 12KB 后起始地址未变，旧数据仍可读；若后续需更大空间可再改回或适当增大。
- NVS_SECTOR_SIZE 保持 4KB，无需改为 12K；12K 是**分区总大小**，不是单扇区大小。
