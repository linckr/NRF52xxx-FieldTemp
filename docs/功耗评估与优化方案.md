# 功耗评估与优化方案

## 1. 当前功耗分析

### 1.1 硬件规格

- **芯片**: nRF52810
- **电池**: CR2032 (3V, 220mAh 典型容量)
- **传感器**: AHT30 温湿度传感器

### 1.2 当前程序功耗来源

| 组件          | 状态                 | 功耗估算     | 说明                              |
| ------------- | -------------------- | ------------ | --------------------------------- |
| **蓝牙广播**  | 快速广播 (100-150ms) | **5-8 mA**   | `BT_LE_ADV_CONN_FAST_1`，功耗最高 |
| **MCU 运行**  | 全速运行             | **4-5 mA**   | 主循环每 1 秒唤醒，未进入低功耗   |
| **LED 闪烁**  | 500ms 间隔           | **1-2 mA**   | 两个 LED 定期闪烁                 |
| **I2C 通信**  | 每 3 秒读取          | **0.5-1 mA** | AHT30 传感器读取                  |
| **UART 输出** | 持续打印             | **0.5-1 mA** | 串口输出（可关闭）                |
| **其他外设**  | 保持运行             | **0.5-1 mA** | GPIO、时钟等                      |
| **总计**      | -                    | **12-18 mA** | 持续运行                          |

### 1.3 电池续航计算

#### 当前功耗模式

- **平均功耗**: 15 mA (保守估算)
- **电池容量**: 220 mAh
- **续航时间**: 220 mAh ÷ 15 mA = **14.7 小时** ≈ **15 小时**

**结论**: 使用 CR2032 电池，当前程序只能运行约 **15 小时**，不适合长期使用。

## 2. nRF52810 功耗特性

### 2.1 不同工作模式功耗

| 模式                      | 功耗       | 说明                   |
| ------------------------- | ---------- | ---------------------- |
| **运行模式**              | 4-5 mA     | CPU 全速运行           |
| **System ON (浅度睡眠)**  | 1-2 μA     | 保持 RAM，可被中断唤醒 |
| **System OFF (深度睡眠)** | 0.4-1.5 μA | 最低功耗，RAM 丢失     |
| **蓝牙广播 (慢速)**       | 0.1-0.3 mA | 间隔 1-2 秒            |
| **蓝牙广播 (快速)**       | 5-8 mA     | 间隔 100-150ms         |
| **蓝牙连接**              | 0.5-2 mA   | 取决于连接间隔         |

### 2.2 优化目标

理想情况下，使用低功耗模式可以实现：

- **未连接时**: 0.5-1 mA (慢速广播 + 浅度睡眠)
- **已连接时**: 1-2 mA (连接模式 + 浅度睡眠)
- **深度睡眠**: 0.4-1.5 μA (仅在不需要蓝牙时)

## 3. 优化方案

### 3.1 方案一：基础低功耗优化（推荐）

**目标功耗**: 1-2 mA，续航 **110-220 小时** (4.5-9 天)

#### 优化措施

1. **启用 Zephyr 电源管理**

   ```conf
   CONFIG_PM=y
   CONFIG_PM_DEVICE=y
   ```

2. **优化蓝牙广播间隔**

   - 从快速广播改为慢速广播
   - `BT_LE_ADV_CONN_SLOW_1`: 间隔 1-2 秒
   - 功耗降低: 5-8 mA → 0.1-0.3 mA

3. **减少 LED 闪烁频率**

   - 未连接时: 2-5 秒闪烁一次
   - 已连接时: 关闭 LED 或极慢闪烁

4. **优化主循环**

   - 使用 `k_sleep()` 进入系统低功耗模式
   - 增加睡眠时间到 3-5 秒
   - 传感器读取间隔改为 30-60 秒

5. **关闭 UART 输出（可选）**
   - 生产环境关闭 `CONFIG_PRINTK=n`
   - 或使用条件编译控制输出

#### 预期效果

- **功耗**: 1-2 mA
- **续航**: 110-220 小时 (4.5-9 天)
- **实现难度**: ⭐⭐ (简单)

---

### 3.2 方案二：深度低功耗优化

**目标功耗**: 0.5-1 mA，续航 **220-440 小时** (9-18 天)

#### 优化措施

在方案一基础上，增加：

1. **智能广播策略**

   - 前 30 秒: 快速广播（便于发现）
   - 之后: 慢速广播（降低功耗）
   - 或使用定向广播（仅连接时广播）

2. **传感器读取优化**

   - 仅在需要时读取（连接时或定时）
   - 未连接时: 每 5-10 分钟读取一次
   - 已连接时: 按需读取（手机请求时）

3. **LED 完全关闭**

   - 仅在关键事件时短暂闪烁（如连接成功）
   - 其他时间完全关闭

4. **外设电源管理**
   - I2C 总线在空闲时关闭
   - 传感器可进入低功耗模式（如果支持）

#### 预期效果

- **功耗**: 0.5-1 mA
- **续航**: 220-440 小时 (9-18 天)
- **实现难度**: ⭐⭐⭐ (中等)

---

### 3.3 方案三：极致低功耗（不推荐）

**目标功耗**: 0.1-0.5 mA，续航 **440-2200 小时** (18-91 天)

#### 优化措施

1. **间歇广播模式**

   - 广播 10 秒，休眠 50 秒
   - 使用定时器唤醒

2. **传感器休眠**

   - 仅在需要时唤醒传感器
   - 使用外部中断触发

3. **System OFF 模式**
   - 在不需要蓝牙时进入深度睡眠
   - 使用 RTC 定时唤醒

**注意**: 此方案会严重影响用户体验（连接困难），不推荐用于需要频繁连接的应用。

AI 追加方案

你这份功耗分析非常专业，它清晰地展示了为什么你的设备现在只能撑 **15 小时**：因为你的芯片目前处于“**全速奔跑**”状态，而真正的低功耗产品大部分时间应该在“**深度睡眠**”。

要达到你预期的 **30 天甚至一年**，关键不在于电池的大小，而在于**占空比（Duty Cycle）**。也就是说，我们要让芯片 99.9% 的时间都在睡觉，只有 0.1% 的时间出来干活。

以下是实现“一年续航”的三个核心武器：

---

### 1. 消除“隐形”的功耗大户（必做）

在你的表格中，有几项功耗在低功耗设计中是不允许存在的：

- **UART 串口 (0.5-1 mA)**：串口驱动开启后，底板上的 CP2102 芯片和 MCU 的 UART 模块会一直耗电。
- **做法**：在正式版本中完全关闭 `CONFIG_SERIAL`。调试时使用 RTT 或仅在必要时开启。

- **LED 闪烁 (1-2 mA)**：对于电池产品，LED 是奢侈品。
- **做法**：取消循环闪烁。改为“按键后闪一下”或“连接成功闪三下”，平时保持熄灭。

- **MCU 全速运行 (4-5 mA)**：这是最大的问题。
- **做法**：必须确保进入 `System ON` 睡眠模式。在 Zephyr 中，只要没有线程在忙，`k_sleep()` 会自动让内核进入低功耗。

---

### 2. 核心参数：如何撑到 1 年？

要撑到一年（约 8760 小时），对于 220mAh 的电池，**平均电流必须控制在 （微安）以下**。

#### 优化后的功耗模型表

| 动作                     | 持续电流 | 持续时间 | 频率         | 平均电流贡献 |
| ------------------------ | -------- | -------- | ------------ | ------------ |
| **深度睡眠 (System ON)** | \*\*\*\* | 一直保持 | 持续         | \*\*\*\*     |
| **蓝牙广播 (慢速)**      | (峰值)   |          | 每 2 秒一次  | \*\*\*\*     |
| **传感器读取 (AHT30)**   |          |          | 每 60 秒一次 | \*\*\*\*     |
| **总计平均电流**         | -        | -        | -            | \*\*\*\*     |

**计算结论**： 小时 **377 天**。

---

### 3. 实现“一年续航”的代码级改动

#### A. 广播策略（最关键）

不要一直快速广播。使用“阶梯式广播”：

```c
// 初始 30 秒快速广播，方便用户连接
bt_le_adv_start(BT_LE_ADV_CONN_FAST_1, ad, ARRAY_SIZE(ad), NULL, 0);

// 30 秒后切换到极慢广播（比如 2.5 秒一次）
// 这可以让芯片在两次广播之间睡得很死
k_sleep(K_SECONDS(30));
bt_le_adv_stop();
bt_le_adv_start(BT_LE_ADV_PARAM(BT_LE_ADV_OPT_CONNECTABLE, 4000, 4001, NULL), ad, ARRAY_SIZE(ad), NULL, 0);

```

#### B. 硬件配置 (prj.conf)

必须关闭掉所有不必要的外设硬件时钟：

```text
# 核心低功耗开关
CONFIG_PM=y
CONFIG_SERIAL=n
CONFIG_UART_CONSOLE=n
CONFIG_CONSOLE=n

# 禁用浮点运算以减少寄存器保护功耗（如果没用到复杂计算）
CONFIG_FPU=n

# 确保使用内部低速时钟，避免外部晶振一直起振
CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC=y

```

#### C. DCDC 转换器（硬件加速）

nRF52810 内部有一个高效的 DCDC。开启它可以将射频电流降低约 40%。
**前提条件**：你的亿佰特模块电路必须焊了 DCDC 所需的电感（通常模块内部已带）。

```text
CONFIG_BOARD_ENABLE_DCDC=y

```

---

### 4. 针对 AHT30 的优化

AHT30 在非测量时间会自动进入休眠，但 I2C 总线本身会有漏电。

- **做法**：在读取完传感器后，可以考虑关闭 I2C 控制器，或者将 SDA/SCL 引脚设为模拟输入模式以防漏电。

---

### 5. 关于 AHT30 传感器的连接

既然你问到之前的电路设计：

1. **物理引脚**：在 E104-BT5010A 的典型设计中，**P0.26 (SDA)** 和 **P0.27 (SCL)** 是最标准的 I2C 选型。
2. **上拉电阻**：如果你的底板没有焊接 的上拉电阻，I2C 即使代码对了也通不了。请确认你的 AHT30 模块上是否自带了电阻。
