# 蓝牙获取手机时间方案设计

## 方案概述

在蓝牙连接建立后，设备需要从手机获取当前时间信息，用于同步设备内部时钟。考虑到 **nRF52810 内存有限**，采用 **自定义 GATT 服务** 的方式，让手机应用主动推送时间到设备。

## 获取手机时间的方式对比

### 自定义 GATT 服务（推荐）⭐

**工作原理：**

- 设备作为 GATT Server，提供可写的时间特性
- 手机应用连接后，主动写入时间到设备
- 设备在写入回调中解析并保存时间

**优点：**

- ✅ 实现简单，代码量小
- ✅ 兼容性好，适用于所有支持 BLE 的手机
- ✅ 内存占用小，适合 nRF52810
- ✅ 手机端实现灵活，可以自定义时间格式

**缺点：**

- ❌ 需要手机端应用支持（需要开发手机 App 或使用现有工具）

**适用场景：** 推荐使用，适合大多数应用场景

## 推荐方案：自定义 GATT 时间服务

### 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    手机应用 (GATT Client)                    │
├─────────────────────────────────────────────────────────────┤
│  连接后自动写入时间 → 时间特性 (可写)                        │
│  时间格式: Unix 时间戳 (uint32_t) 或 结构化时间              │
└─────────────────────────────────────────────────────────────┘
                        ↓ 蓝牙连接
┌─────────────────────────────────────────────────────────────┐
│                  E104-BT5010A 设备 (GATT Server)             │
├─────────────────────────────────────────────────────────────┤
│  GATT Server                                                │
│  ├── Time Sync Service (自定义 UUID)                        │
│  │   └── Current Time Characteristic (可写)                 │
│  │       └── 数据格式: Unix 时间戳 (uint32_t)               │
│  │       └── 或结构化时间 (年/月/日/时/分/秒)                │
│  └── 写入回调处理 → 解析时间 → 更新系统时钟                  │
├─────────────────────────────────────────────────────────────┤
│  数据流:                                                    │
│  手机连接 → 写入时间 → 设备接收 → 解析时间 → 同步系统时钟    │
└─────────────────────────────────────────────────────────────┘
```

### 详细设计

#### 服务定义

| 项目               | 说明                                                               |
| ------------------ | ------------------------------------------------------------------ |
| **服务 UUID**      | `12340010-1234-5678-1234-56789ABCDEF0` (自定义)                    |
| **时间特性 UUID**  | `12340011-1234-5678-1234-56789ABCDEF0`                             |
| **特性权限**       | Write (可写)                                                       |
| **时间格式选项 1** | Unix 时间戳 (uint32_t)，从 1970-01-01 00:00:00 UTC 的秒数          |
| **时间格式选项 2** | 结构化时间 (7 字节): 年(2) + 月(1) + 日(1) + 时(1) + 分(1) + 秒(1) |
| **更新方式**       | 手机应用在连接后主动写入，或定期更新                               |
| **时区处理**       | 可选：增加时区特性，或时间戳使用 UTC，设备本地转换                 |

#### 时间格式对比

**格式 1：Unix 时间戳 (推荐)**

- **大小：** 4 字节 (uint32_t)
- **范围：** 1970-01-01 ~ 2106-02-07
- **优点：**
  - 数据量小，传输效率高
  - 手机端获取简单 (`System.currentTimeMillis() / 1000`)
  - 包含时区信息（UTC）
- **缺点：**
  - 需要设备端转换计算

**格式 2：结构化时间**

- **大小：** 7 字节
- **格式：** `[年高字节][年低字节][月][日][时][分][秒]`
- **优点：**
  - 直观易懂
  - 设备端解析简单
- **缺点：**
  - 数据量稍大
  - 不包含时区信息
  - 需要手机端格式化

**推荐：** 使用 Unix 时间戳格式，更通用且高效

### 功能特性

1. **自动时间同步** - 手机连接后自动写入时间
2. **定期更新** - 手机应用可定期更新设备时间（可选）
3. **时区支持** - 支持 UTC 时间戳，设备可本地转换
4. **LED 指示** - DATA LED 在接收时间时闪烁
5. **低功耗** - 仅在写入时处理，无额外开销

### 实现流程

```
1. 设备启动
   ↓
2. 初始化蓝牙 GATT Server
   ↓
3. 注册时间服务 (Time Sync Service)
   ↓
4. 注册时间特性 (Current Time Characteristic, 可写)
   ↓
5. 手机连接
   ↓
6. 手机应用写入时间到特性
   ↓
7. 设备接收写入回调
   ↓
8. 解析时间数据 (Unix 时间戳)
   ↓
9. 更新系统时钟 (使用 Zephyr RTC 或系统时间 API)
   ↓
10. 打印时间同步成功信息
```

### Zephyr API 使用

**时间相关 API：**

- `k_uptime_get()` - 获取系统运行时间（毫秒）
- `k_uptime_ticks()` - 获取系统运行时间（tick）
- RTC 驱动（如果硬件支持）

**注意：** nRF52810 没有硬件 RTC，可以使用软件计时器或系统运行时间 + 基准时间戳来计算当前时间。

### 手机端实现建议

**Android 示例：**

```java
// 获取当前时间戳（秒）
long timestamp = System.currentTimeMillis() / 1000;
byte[] timeData = ByteBuffer.allocate(4)
    .order(ByteOrder.LITTLE_ENDIAN)
    .putInt((int)timestamp)
    .array();

// 写入到特性
bluetoothGattCharacteristic.setValue(timeData);
bluetoothGatt.writeCharacteristic(bluetoothGattCharacteristic);
```

**iOS 示例：**

```swift
// 获取当前时间戳（秒）
let timestamp = UInt32(Date().timeIntervalSince1970)
let timeData = withUnsafeBytes(of: timestamp.littleEndian) { Data($0) }

// 写入到特性
characteristic.writeValue(timeData, type: .withResponse)
```

### 使用 nRF Connect 测试

nRF Connect 是 Nordic 官方提供的蓝牙调试工具，可以用于测试和验证 GATT 时间服务。

#### 连接步骤

1. **打开 nRF Connect**

   - 在手机上安装并打开 nRF Connect 应用

2. **扫描设备**

   - 点击 "Scan" 按钮开始扫描
   - 查找设备名称：`yodfz-temp`（或配置的设备名称）
   - 点击设备进行连接

3. **查找时间服务**
   - 连接成功后，在服务列表中查找：
     - **服务 UUID：** `12340010-1234-5678-1234-56789ABCDEF0`
     - **特性 UUID：** `12340011-1234-5678-1234-56789ABCDEF0`（可写）

#### 发送时间数据

**数据格式：** Unix 时间戳（uint32_t，小端序）

- **大小：** 4 字节
- **格式：** 从 1970-01-01 00:00:00 UTC 的秒数
- **字节序：** 小端序（Little Endian）

**操作步骤：**

1. **点击时间特性**

   - 在服务列表中找到时间特性（UUID: `12340011-1234-5678-1234-56789ABCDEF0`）
   - 点击特性进入详情页面

2. **选择写入方式**

   - 点击 "Write" 或 "Write without response" 按钮
   - 推荐使用 "Write"（带响应，更可靠）

3. **输入时间数据（十六进制）**
   - 选择输入格式为 "Hex"（十六进制）
   - 计算当前 Unix 时间戳并转换为小端序十六进制

**时间戳计算方法：**

```python
# Python 示例：计算当前时间戳
import time
timestamp = int(time.time())  # 当前 Unix 时间戳（秒）
# 例如：1704067200 (2024-01-01 00:00:00 UTC)

# 转换为小端序十六进制
hex_str = format(timestamp, '08X')  # '65A8C800'
# 小端序字节：00 C8 A8 65
```

**示例数据：**

假设当前时间是 **2024-01-01 00:00:00 UTC**：

- Unix 时间戳（十进制）：`1704067200`
- Unix 时间戳（十六进制）：`65A8C800`
- 小端序字节序列：`00 C8 A8 65`
- **在 nRF Connect 中输入：** `00 C8 A8 65`

**实时时间戳获取：**

可以使用在线工具或命令行获取当前时间戳：

- **在线工具：** https://www.epochconverter.com/
- **命令行（Linux/Mac）：** `date +%s`
- **命令行（Windows PowerShell）：** `[int][double]::Parse((Get-Date -UFormat %s))`

**验证写入成功：**

写入成功后，设备应该：

- 在串口输出时间同步成功信息
- DATA LED 闪烁（如果已实现 LED 指示功能）
- 设备内部时钟更新为写入的时间

**注意事项：**

1. **字节序：** 必须使用小端序（Little Endian），即低字节在前
2. **数据长度：** 必须严格为 4 字节，不能多也不能少
3. **时间范围：** Unix 时间戳范围是 1970-01-01 ~ 2106-02-07
4. **时区：** 时间戳使用 UTC 时间，设备端可根据需要转换为本地时间

### 内存占用估算

- GATT 服务定义：~200 字节
- 特性定义：~100 字节
- 写入回调处理：~100 字节
- **总计：** ~400 字节（在 nRF52810 可接受范围内）

### 扩展功能（可选）

1. **时区特性** - 添加时区偏移特性，支持本地时间
2. **时间请求** - 设备可主动请求时间（需要 GATT Client 支持）
3. **时间验证** - 验证时间合理性（范围检查）
4. **时间同步状态** - 添加只读特性，指示时间是否已同步

**推荐方案：** 使用自定义 GATT 服务，设备作为 Server，手机应用写入 Unix 时间戳。

**优势：**

- ✅ 实现简单，内存占用小
- ✅ 兼容性好，适用于所有手机
- ✅ 传输效率高（4 字节）
- ✅ 适合 nRF52810 资源限制
