# 历史数据增量获取方案

## 功能概述

历史数据增量获取功能允许手机端通过携带最后一条数据的时间戳，只获取时间戳大于该值的新数据，避免重复传输已有数据，提高传输效率。

## 问题背景

在之前的实现中，当手机端启用历史数据通知时，设备端会从最旧的数据开始发送全部历史数据。这导致以下问题：

1. **重复传输**：手机端已经有的数据会被重复传输
2. **传输效率低**：大量已存在的数据占用传输带宽和时间
3. **功耗增加**：长时间的数据传输增加设备功耗

## 解决方案

### 设计思路

1. **手机端携带时间戳**：请求历史数据时，携带最后一条数据的时间戳
2. **设备端过滤数据**：只发送时间戳大于设定值的数据
3. **按时间顺序发送**：保持数据按时间戳从旧到新的顺序发送

### 实现方式

#### 1. GATT 特性修改

历史数据特性 (`UUID: 12340023-1234-5678-1234-56789ABCDEF0`) 从**只通知**改为**可写+可通知**：

- **写入权限**：允许手机端写入起始时间戳（4字节，小端序）
- **通知权限**：设备端通过通知发送历史数据

#### 2. 数据格式

**写入数据格式（手机端 → 设备端）：**
- 长度：4 字节
- 格式：uint32_t，小端序（Little-Endian）
- 含义：Unix 时间戳（秒）
- 特殊值：`0` 表示发送全部历史数据

**通知数据格式（设备端 → 手机端）：**
- 格式：与之前相同，每条记录 8 字节
  - 时间戳：4 字节（uint32_t，小端序）
  - 温度：2 字节（int16_t，单位 0.01°C，小端序）
  - 湿度：2 字节（uint16_t，单位 0.01%，小端序）
- 每个通知包最多包含 2 条记录（16 字节）

## 使用流程

### 手机端操作步骤

1. **写入起始时间戳**
   ```javascript
   // 示例：最后一条数据的时间戳为 1704067200
   const timestamp = 1704067200;
   const buffer = new ArrayBuffer(4);
   const view = new DataView(buffer);
   view.setUint32(0, timestamp, true); // true 表示小端序
   
   // 写入到历史数据特性
   await characteristic.writeValue(buffer);
   ```

2. **启用通知**
   ```javascript
   await characteristic.startNotifications();
   ```

3. **接收数据**
   ```javascript
   characteristic.addEventListener('characteristicvaluechanged', (event) => {
       const value = event.target.value;
       // 处理接收到的历史数据
   });
   ```

### 设备端处理流程

```
手机端写入时间戳
    ↓
设备端保存起始时间戳 (history_start_timestamp)
    ↓
手机端启用通知
    ↓
设备端开始遍历存储数据
    ↓
过滤：只发送 timestamp > history_start_timestamp 的记录
    ↓
按时间顺序发送数据包
    ↓
发送结束标志 (0xFF)
```

## 示例场景

### 场景描述

假设设备存储了以下历史数据：

| ID | 时间戳      | 温度   | 湿度   |
|----|------------|--------|--------|
| 1  | 1704067000 | 25.5°C | 60.0%  |
| 2  | 1704067100 | 26.0°C | 61.0%  |
| 3  | 1704067200 | 26.5°C | 62.0%  ← 手机端已有
| 4  | 1704067300 | 27.0°C | 63.0%  |
| 5  | 1704067400 | 27.5°C | 64.0%  |

### 操作步骤

1. **手机端写入时间戳**
   - 写入值：`1704067200`（最后一条已有数据的时间戳）
   - 字节序列（小端序）：`[0x00, 0xE6, 0x0F, 0x65]`

2. **手机端启用通知**
   - 调用 `startNotifications()`

3. **设备端响应**
   - 设备端收到时间戳后，保存为 `history_start_timestamp = 1704067200`
   - 开始遍历存储数据
   - 过滤结果：
     - ID 1: 时间戳 1704067000 ≤ 1704067200，**跳过**
     - ID 2: 时间戳 1704067100 ≤ 1704067200，**跳过**
     - ID 3: 时间戳 1704067200 ≤ 1704067200，**跳过**
     - ID 4: 时间戳 1704067300 > 1704067200，**发送**
     - ID 5: 时间戳 1704067400 > 1704067200，**发送**

4. **传输结果**
   - 只传输 ID 4 和 ID 5 的数据
   - 避免了 ID 1、2、3 的重复传输

## 代码实现细节

### 设备端关键变量

```c
// 起始时间戳（0 表示发送全部数据）
static uint32_t history_start_timestamp = 0;
```

### 写入回调函数

```c
static ssize_t history_char_write_cb(struct bt_conn *conn,
                                      const struct bt_gatt_attr *attr,
                                      const void *buf, uint16_t len, uint16_t offset,
                                      uint8_t flags)
{
    // 检查数据长度（必须是4字节）
    if (len != 4) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_ATTRIBUTE_LEN);
    }

    // 解析起始时间戳（小端序）
    uint32_t timestamp = sys_get_le32(buf);
    
    // 保存起始时间戳
    history_start_timestamp = timestamp;
    
    // timestamp == 0 表示发送全部数据
    return len;
}
```

### 数据过滤逻辑

在发送数据时，过滤掉时间戳小于等于起始时间戳的记录：

```c
// 遍历当前批次的数据
for (int i = 0; i < 2 && (history_transfer_record_idx + i) < record_count; i++) {
    struct data_record *rec = &buf[history_transfer_record_idx + i];
    
    // 如果设置了起始时间戳，过滤掉时间戳小于等于的记录
    if (history_start_timestamp > 0 && rec->timestamp <= history_start_timestamp) {
        continue;  // 跳过这条记录
    }
    
    // 复制符合条件的数据到发送缓冲区
    memcpy(&tx_buf[tx_len], rec, sizeof(struct data_record));
    tx_len += sizeof(struct data_record);
}
```

## 注意事项

### 1. 时间戳格式

- **必须使用小端序**（Little-Endian）编码
- 时间戳单位为**秒**（Unix 时间戳）
- 时间戳为 `0` 时，设备端会发送全部历史数据

### 2. 数据顺序

- 数据按**时间戳从旧到新**的顺序发送
- 即使设置了起始时间戳，顺序仍然保持

### 3. 状态保持

- 起始时间戳在传输完成后**不会自动清除**
- 下次启用通知时，如果未重新写入时间戳，将使用上次的值
- 如需发送全部数据，需要先写入 `0`，再启用通知

### 4. 边界情况

- **时间戳为 0**：发送全部历史数据
- **时间戳大于所有数据**：不发送任何数据（传输立即完成）
- **时间戳等于最新数据**：不发送任何数据（传输立即完成）

## 优势

1. **减少传输量**：只传输增量数据，大幅减少传输时间
2. **降低功耗**：缩短传输时间，降低设备功耗
3. **提高效率**：避免重复数据，提高整体系统效率
4. **向后兼容**：写入 `0` 仍可获取全部数据，保持兼容性

## 测试建议

### 测试场景 1：增量获取

1. 设备存储 100 条历史数据
2. 手机端已有最后 50 条数据（时间戳范围：1704067200-1704067700）
3. 写入时间戳 `1704067200`
4. 启用通知
5. 验证：只收到 50 条新数据

### 测试场景 2：获取全部数据

1. 设备存储 100 条历史数据
2. 写入时间戳 `0`
3. 启用通知
4. 验证：收到全部 100 条数据

### 测试场景 3：无新数据

1. 设备存储 100 条历史数据
2. 写入时间戳 `1704068000`（大于所有数据的时间戳）
3. 启用通知
4. 验证：立即收到结束标志（0xFF），无数据包
