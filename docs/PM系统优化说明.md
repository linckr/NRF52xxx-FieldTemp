# PM 系统优化说明

## 什么是 PM 系统？

**PM（Power Management，电源管理）系统**是 Zephyr RTOS 提供的低功耗管理框架，可以自动让 MCU 进入低功耗模式，大幅降低功耗。

---

## PM 系统如何降低功耗？

### 当前状态（未启用 PM）

**主循环代码：**
```c
while (1) {
    k_sleep(K_SECONDS(10));  // CPU 进入空闲，但功耗仍然较高
}
```

**功耗情况：**
- CPU 虽然进入空闲，但**没有进入低功耗模式**
- 系统时钟仍在运行
- 外设时钟可能未关闭
- **功耗：约 4-5 mA**

### 启用 PM 系统后

**工作原理：**
1. 当所有线程都进入睡眠（`k_sleep()`）时
2. PM 系统**自动检测**到系统空闲
3. **自动关闭**不需要的外设时钟
4. **降低 CPU 频率**或进入 **System ON 睡眠模式**
5. 由定时器或中断**自动唤醒**

**功耗情况：**
- CPU 进入 **System ON 睡眠模式**
- 大部分外设时钟关闭
- 仅保留必要的唤醒源（定时器、蓝牙中断等）
- **功耗：约 1-2 μA**（睡眠时）

---

## 功耗对比

| 状态 | 未启用 PM | 启用 PM | 节省 |
|------|----------|---------|------|
| **运行模式** | 4-5 mA | 4-5 mA | 0 |
| **空闲/睡眠** | 4-5 mA | **1-2 μA** | **约 4-5 mA** |
| **平均功耗** | 4-5 mA | **0.5-2 mA** | **约 3-4 mA** |

**关键点：**
- 系统大部分时间处于空闲状态（等待定时器、蓝牙事件）
- PM 系统让空闲时功耗从 **4-5 mA 降至 1-2 μA**
- **这是最大的功耗优化项！**

## PM 系统的工作模式

### nRF52810 支持的功耗模式

| 模式 | 功耗 | 说明 | 唤醒方式 |
|------|------|------|---------|
| **运行模式** | 4-5 mA | CPU 全速运行 | - |
| **System ON (浅度睡眠)** | **1-2 μA** | RAM 保持，外设可唤醒 | 定时器、GPIO、蓝牙中断 |
| **System OFF (深度睡眠)** | 0.4-1.5 μA | RAM 丢失，需要复位 | 复位、GPIO 唤醒 |

**PM 系统通常使用 System ON 模式：**
- ✅ RAM 数据保持（不需要重新初始化）
- ✅ 功耗极低（1-2 μA）
- ✅ 可被定时器和蓝牙中断唤醒

## 如何启用 PM 系统？

### 步骤 1：确保配置正确

**prj.conf：**
```conf
# 电源管理
CONFIG_PM=y
CONFIG_PM_DEVICE=y          # 启用设备级电源管理
CONFIG_PM_DEVICE_RUNTIME=y  # 启用运行时电源管理（可选）
```

### 步骤 2：修复代码问题

**问题：** USAGE FAULT (PC=0x00000000) - 可能是 PM 回调函数空指针

**解决方案 A：最小化 PM 使用（推荐）**

实际上，**如果只使用 `k_sleep()`，PM 系统应该能自动工作**，不需要显式包含 PM 头文件！

**测试方法：**
1. 保持当前代码（PM 头文件注释掉）
2. 确保 `CONFIG_PM=y` 已启用
3. 使用 `k_sleep()` 让系统进入空闲
4. **测量功耗**，看是否进入低功耗模式

**如果功耗仍然很高（4-5 mA），说明 PM 没有生效。**

**解决方案 B：修复 PM 回调问题**

如果需要显式使用 PM API，需要修复回调函数：

```c
#include <zephyr/pm/pm.h>
#include <zephyr/pm/policy.h>

// 定义 PM 策略回调（如果需要）
static void pm_policy_cb(struct pm_state_info *info)
{
    // 实现 PM 策略
    // 注意：确保回调函数不为空
}
```

### 步骤 3：验证 PM 是否工作

**方法 1：功耗测试**
- 测量系统空闲时的功耗
- 如果从 4-5 mA 降至 1-2 μA，说明 PM 工作正常

**方法 2：代码检查**
```c
// 在 k_sleep() 前后打印信息
printk("准备进入睡眠...\n");
k_sleep(K_SECONDS(10));
printk("从睡眠中唤醒\n");
```

**方法 3：使用 PM 统计（如果支持）**
```c
#include <zephyr/pm/pm_stats.h>

// 查看 PM 统计信息
pm_stats_dump();
```

## 为什么当前 PM 可能没有生效？

### 可能的原因

1. **PM 头文件被注释**
   - 虽然 `CONFIG_PM=y`，但可能某些初始化代码被跳过

2. **外设阻止进入低功耗**
   - UART 持续输出可能阻止睡眠
   - 某些外设未正确配置为低功耗模式

3. **定时器配置问题**
   - 如果定时器配置不当，系统可能无法进入睡眠

4. **蓝牙阻止睡眠**
   - 蓝牙广播时，系统可能无法进入深度睡眠
   - 但应该能进入 System ON 模式

### 检查清单

- [ ] `CONFIG_PM=y` 已启用
- [ ] 主循环使用 `k_sleep()` 或 `k_msleep()`
- [ ] 没有阻塞的线程
- [ ] UART 在睡眠时关闭（如果可能）
- [ ] 外设配置了低功耗模式

## 优化建议

### 方案 1：先测试当前状态（最简单）

1. **保持当前代码**（PM 头文件注释）
2. **确保 `CONFIG_PM=y`**
3. **测量功耗**：
   - 如果空闲时功耗是 1-2 μA → PM 已工作 ✅
   - 如果空闲时功耗是 4-5 mA → PM 未工作 ❌

### 方案 2：修复 PM 回调问题（如果需要）

如果方案 1 测试发现 PM 未工作，需要：

1. **检查是否有 PM 回调函数**
2. **确保回调函数不为空**
3. **或者移除不必要的 PM 回调**

### 方案 3：使用设备级 PM（推荐）

**在设备树中配置外设低功耗：**

```dts
&uart0 {
    status = "okay";
    // 启用运行时 PM
    zephyr,pm-device-runtime-auto;
};
```

**在代码中手动管理外设：**
```c
#include <zephyr/pm/device.h>

// 外设使用完后，手动挂起
pm_device_action_run(uart_dev, PM_DEVICE_ACTION_SUSPEND);
```
