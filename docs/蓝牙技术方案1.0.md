# 安卓端开发通讯技术方案

## 1. 方案概述

本文档详细说明安卓端与 E104-BT5010A 蓝牙温湿度采集设备的通讯技术方案，包括蓝牙连接、GATT 服务交互、数据格式定义和实现示例。

### 1.1 设备信息

- **设备名称**: `PandaTemperature` (默认配置，可在 `prj.conf` 中修改为其他名称如 `yodfz-temp`)
- **设备类型**: BLE (Bluetooth Low Energy) 外设
- **芯片平台**: nRF52810
- **通讯协议**: BLE GATT (Generic Attribute Profile)

### 1.2 通讯架构

```
┌─────────────────────────────────────────────────────────────┐
│                    安卓应用 (GATT Client)                    │
├─────────────────────────────────────────────────────────────┤
│  1. 扫描并连接设备                                           │
│  2. 发现 GATT 服务                                           │
│  3. 读取/写入特性值                                          │
│  4. 订阅通知接收数据（实时数据 + 历史数据）                   │
└─────────────────────────────────────────────────────────────┘
                        ↓ 蓝牙 BLE 连接
┌─────────────────────────────────────────────────────────────┐
│              E104-BT5010A 设备 (GATT Server)                 │
├─────────────────────────────────────────────────────────────┤
│  GATT 服务列表:                                             │

│      ├── 时间同步特性 (Time Sync)                            │
│      ├── 采集间隔特性 (Sample Interval)                      │
│      ├── 设备状态特性 (Device Status)                        │
│      └── 历史数据特性 (History Data)                         │
└─────────────────────────────────────────────────────────────┘
```

## 2. GATT 服务定义

### 2.1 环境感知服务 (Environmental Sensing Service)

标准蓝牙服务，用于传输实时温湿度数据。

- **服务 UUID**: `0000181A-0000-1000-8000-00805f9b34fb` (16-bit UUID: `0x181A`)

#### 温度特性 (Temperature Characteristic)

- **UUID**: `00002A6E-0000-1000-8000-00805f9b34fb` (16-bit UUID: `0x2A6E`)
- **权限**: Read + Notify (可读/可通知)
- **数据格式**: int16_t (2 字节)
- **单位**: 0.01°C (实际值 = 读取值 / 100)
- **示例**: `0x092E` (2350) -> 23.50°C

#### 湿度特性 (Humidity Characteristic)

- **UUID**: `00002A6F-0000-1000-8000-00805f9b34fb` (16-bit UUID: `0x2A6F`)
- **权限**: Read + Notify (可读/可通知)
- **数据格式**: uint16_t (2 字节)
- **单位**: 0.01% (实际值 = 读取值 / 100)
- **示例**: `0x1964` (6500) -> 65.00%

---

### 2.2 配置服务 (Config Service)

自定义服务，包含设备配置、控制和历史数据传输功能。

- **服务 UUID**: `12340020-1234-5678-1234-56789abcdef0` (注意：小写格式)

#### 1. 时间同步特性 (Time Sync Characteristic)

- **UUID**: `12340011-1234-5678-1234-56789abcdef0` (注意：小写格式)
- **权限**: Write (可写)
- **功能**: 同步设备 RTC 时间
- **数据格式**: uint32_t (4 字节, Unix 时间戳, 小端序)
- **示例**: 当前时间戳 `Math.floor(Date.now() / 1000)` 写入

#### 2. 采集间隔特性 (Sample Interval Characteristic)

- **UUID**: `12340021-1234-5678-1234-56789abcdef0` (注意：小写格式)
- **权限**: Read + Write (可读/可写)
- **功能**: 设置温湿度自动采集的间隔时间
- **数据格式**: uint16_t (2 字节, 秒, 小端序)
- **范围**: 10 ~ 3600 秒 (默认 30 秒)
- **验证**: App 端写入前应检查范围，防止无效值

#### 3. 设备状态特性 (Device Status Characteristic)

- **UUID**: `12340022-1234-5678-1234-56789abcdef0` (注意：小写格式)
- **权限**: Read + Notify (可读/可通知)
- **功能**: 实时反馈设备运行状态
- **数据格式**: 6 字节结构体 (小端序)
  - `[0-1]`: 采集间隔 (uint16_t, Little Endian)
  - `[2-3]`: 当前存储记录数 (uint16_t, Little Endian)
  - `[4]`: 系统状态标志位 (uint8_t)
    - **Bit 0 (0x01)**: 设备连接状态 (1=已连接, 0=未连接)
    - **Bit 1 (0x02)**: 时间同步状态 (1=已同步, 0=未同步)
    - **Bit 2-7**: 保留未使用
  - `[5]`: 保留字节 (未使用)
- **使用建议**:
  - 首次连接后调用 `readValue()` 读取一次
  - 调用 `startNotifications()` 订阅状态更新，实现实时监控
  - 状态变化时会自动推送通知

#### 4. 历史数据特性 (History Data Characteristic) - **获取列表的核心**

- **UUID**: `12340023-1234-5678-1234-56789abcdef0` (注意：小写格式)
- **权限**: Notify (仅通知)
- **功能**: 批量传输 Flash 中存储的历史温湿度记录
- **交互流程**:
  1. App 调用 `startNotifications()` 启用 Notification (自动写入 CCCD 0x2902)
  2. 设备自动开始读取 Flash，并通过 Notification 持续推送数据包
  3. App 在 `onCharacteristicChanged` 回调中接收并解析数据包
  4. 数据传输完成后，设备发送一个单字节包 `[0xFF]` 作为结束标志
  5. App 检测到结束标志后，停止通知并更新 UI 列表
- **数据包格式**:
  - 每个 Notification 包最大 20 字节（取决于 MTU），通常包含 2 条记录 (每条 8 字节)
  - 最后一个包可能包含不完整的记录（需要根据实际长度解析）
  - **记录结构 (8 bytes, Little Endian)**:
    - `Timestamp` (4 bytes, uint32_t, Unix 时间戳，0 表示未同步时间)
    - `Temperature` (2 bytes, int16_t, 0.01°C 单位)
    - `Humidity` (2 bytes, uint16_t, 0.01% 单位)
  - **结束标志**: 单字节包，值为 `0xFF`
- **实现要点**:
  - **防重复调用**: 在获取过程中应设置标志位，防止用户重复点击
  - **状态清理**: 每次开始获取前，先停止之前的通知并移除旧的事件监听器
  - **超时处理**: 建议设置 60 秒超时，防止长时间等待
  - **数据排序**: 设备可能按存储顺序发送，App 端接收完毕后应按时间戳排序
  - **时间戳为 0**: 如果时间戳为 0，表示该记录采集时设备时间未同步，应特殊处理显示

### 3.2 获取历史数据列表 (关键逻辑)

```java
// 全局变量
private boolean historyFetching = false; // 防止重复点击
private boolean historyComplete = false;
private List<HistoryRecord> historyData = new ArrayList<>();
private Handler historyTimeoutHandler = new Handler();
private Runnable historyTimeoutRunnable;

// 1. 获取特性
BluetoothGattService configService = gatt.getService(UUID.fromString("12340020-1234-5678-1234-56789abcdef0"));
BluetoothGattCharacteristic historyChar = configService.getCharacteristic(UUID.fromString("12340023-1234-5678-1234-56789abcdef0"));

// 2. 获取历史数据 (完整流程)
private void fetchHistory() {
    // 防止重复调用
    if (historyFetching) {
        Log.i("BLE", "历史数据正在获取中，请勿重复点击");
        return;
    }

    historyFetching = true;
    historyComplete = false;
    historyData.clear();

    try {
        // 先停止之前的通知（如果已启动）
        gatt.setCharacteristicNotification(historyChar, false);

        // 等待一小段时间，确保状态清理完成
        Thread.sleep(200);

        // 移除旧的事件监听器（如果有）
        // Android BLE API 会自动处理，但可以在这里清理自定义回调

        // 启用通知 (必须同时设置本地和远程 CCCD)
        gatt.setCharacteristicNotification(historyChar, true);
        BluetoothGattDescriptor descriptor = historyChar.getDescriptor(
            UUID.fromString("00002902-0000-1000-8000-00805f9b34fb"));
        if (descriptor != null) {
            descriptor.setValue(BluetoothGattDescriptor.ENABLE_NOTIFICATION_VALUE);
            gatt.writeDescriptor(descriptor);
        }

        // 设置超时 (60秒)
        historyTimeoutRunnable = () -> {
            if (!historyComplete) {
                Log.w("BLE", "历史数据获取超时，已接收 " + historyData.size() + " 条记录");
                historyFetching = false;
                // 停止通知
                gatt.setCharacteristicNotification(historyChar, false);
                // 显示已接收的数据
                updateHistoryUI();
            }
        };
        historyTimeoutHandler.postDelayed(historyTimeoutRunnable, 60000);

    } catch (Exception e) {
        Log.e("BLE", "获取历史数据失败: " + e.getMessage());
        historyFetching = false;
    }
}

// 3. 在 onCharacteristicChanged 回调中接收数据
@Override
public void onCharacteristicChanged(BluetoothGatt gatt, BluetoothGattCharacteristic characteristic) {
    if (characteristic.getUuid().equals(HISTORY_CHAR_UUID)) {
        byte[] data = characteristic.getValue();

        if (data == null || data.length == 0) {
            Log.w("BLE", "警告: 数据为空");
            return;
        }

        // 检查结束标志
        if (data.length == 1 && (data[0] & 0xFF) == 0xFF) {
            Log.i("BLE", "历史数据传输完成，共 " + historyData.size() + " 条记录");
            historyComplete = true;
            historyFetching = false;

            // 取消超时
            historyTimeoutHandler.removeCallbacks(historyTimeoutRunnable);

            // 停止通知
            gatt.setCharacteristicNotification(historyChar, false);

            // 更新 UI 列表（按时间戳排序）
            Collections.sort(historyData, (a, b) -> Long.compare(a.timestamp, b.timestamp));
            updateHistoryUI();
            return;
        }

        // 解析数据包 (每个包可能包含 1 或 2 条记录，取决于 MTU)
        ByteBuffer buffer = ByteBuffer.wrap(data).order(ByteOrder.LITTLE_ENDIAN);
        int recordsInPacket = 0;

        while (buffer.remaining() >= 8) {
            long timestamp = buffer.getInt() & 0xFFFFFFFFL; // 无符号转换
            short tempRaw = buffer.getShort();
            int humRaw = buffer.getShort() & 0xFFFF; // 无符号转换

            float temperature = tempRaw / 100.0f;
            float humidity = humRaw / 100.0f;

            historyData.add(new HistoryRecord(timestamp, temperature, humidity));
            recordsInPacket++;
        }

        if (recordsInPacket > 0) {
            Log.d("BLE", "解析到 " + recordsInPacket + " 条记录，总计 " + historyData.size() + " 条");
            // 实时更新显示（每20条更新一次，避免卡顿）
            if (historyData.size() % 20 == 0) {
                updateHistoryUI();
            }
        } else {
            Log.w("BLE", "警告: 数据包长度 " + data.length + " 字节，无法解析完整记录");
        }
    }
}

// 4. 历史记录数据类
class HistoryRecord {
    long timestamp;    // Unix 时间戳（秒），0 表示未同步时间
    float temperature; // 温度（摄氏度）
    float humidity;    // 湿度（百分比）

    HistoryRecord(long timestamp, float temperature, float humidity) {
        this.timestamp = timestamp;
        this.temperature = temperature;
        this.humidity = humidity;
    }

    String getTimeString() {
        if (timestamp == 0) {
            return "未同步时间";
        }
        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.getDefault());
        return sdf.format(new Date(timestamp * 1000));
    }
}
```

```java
@Override
public void onCharacteristicRead(BluetoothGatt gatt, BluetoothGattCharacteristic characteristic, int status) {
    if (characteristic.getUuid().equals(STATUS_CHAR_UUID) && status == BluetoothGatt.GATT_SUCCESS) {
        byte[] data = characteristic.getValue();
        ByteBuffer buffer = ByteBuffer.wrap(data).order(ByteOrder.LITTLE_ENDIAN);

        int interval = buffer.getShort() & 0xFFFF;      // [0-1]: 采集间隔
        int recordCount = buffer.getShort() & 0xFFFF;   // [2-3]: 记录数
        byte statusFlags = buffer.get();                // [4]: 状态标志位

        boolean isConnected = (statusFlags & 0x01) != 0;  // Bit 0: 连接状态
        boolean isTimeSynced = (statusFlags & 0x02) != 0; // Bit 1: 时间同步状态

        Log.i("BLE", String.format("设备状态: 间隔=%d秒, 记录数=%d, 连接=%s, 时间同步=%s",
            interval, recordCount, isConnected ? "是" : "否", isTimeSynced ? "是" : "否"));

        // 更新 UI
        updateStatusUI(interval, recordCount, isConnected, isTimeSynced);
    }
}

// 订阅设备状态更新（可选）
private void subscribeDeviceStatus() {
    BluetoothGattCharacteristic statusChar = configService.getCharacteristic(
        UUID.fromString("12340022-1234-5678-1234-56789abcdef0"));

    if (statusChar != null) {
        gatt.setCharacteristicNotification(statusChar, true);
        BluetoothGattDescriptor descriptor = statusChar.getDescriptor(
            UUID.fromString("00002902-0000-1000-8000-00805f9b34fb"));
        if (descriptor != null) {
            descriptor.setValue(BluetoothGattDescriptor.ENABLE_NOTIFICATION_VALUE);
            gatt.writeDescriptor(descriptor);
        }
    }
}
```

```java
// 监听连接断开事件
private final BroadcastReceiver gattUpdateReceiver = new BroadcastReceiver() {
    @Override
    public void onReceive(Context context, Intent intent) {
        final String action = intent.getAction();
        if (BluetoothDevice.ACTION_ACL_DISCONNECTED.equals(action)) {
            BluetoothDevice device = intent.getParcelableExtra(BluetoothDevice.EXTRA_DEVICE);

            // 实现自动重连逻辑

private void attemptReconnect() {
    // 延迟重连，避免频繁重试
    handler.postDelayed(() -> {
        if (gatt != null) {
            gatt.connect();
        }
    }, 2000);
}
```

## 5. 常见问题 (FAQ)

**Q: 为什么找不到温湿度列表的 Read 特性？**
A: BLE 协议不适合一次性读取大块数据（受 MTU 限制，通常为 20-23 字节）。因此我们采用 Notification (通知) 方式。你只需要订阅 History 特性，设备就会主动把数据一条条（或一批批）推送到手机。

**Q: 历史数据怎么排序？**
A: 设备默认按照存储顺序发送（可能是从最旧到最新，取决于 NVS 环形缓冲区的实现）。建议 App 端接收完毕后根据时间戳进行一次排序，确保数据按时间顺序显示。

**Q: 传输速度慢怎么办？**
A:

- 可以尝试请求更大的 MTU (Request MTU)，最大支持 247 字节，但设备可能不支持
- 在连接参数中请求更短的连接间隔 (Connection Interval)，但需要设备支持
- 历史数据传输可能需要 10-60 秒，取决于记录数量，这是正常的

**Q: 时间戳为 0 是什么意思？**
A: 如果历史记录的时间戳为 0，表示该记录采集时设备时间未同步。App 端应特殊处理，显示为"未同步时间"或其他提示信息。

**Q: 如何防止重复获取历史数据？**
A: 在开始获取前设置标志位（如 `historyFetching = true`），获取完成或失败后重置。在标志位为 `true` 时，忽略新的获取请求。

**Q: 设备断开连接后如何处理？**
A: 应该在 `onConnectionStateChange` 回调中监听断开事件，清理资源（停止通知、移除监听器等），并可选实现自动重连机制。

**Q: 订阅通知后没有收到数据怎么办？**
A:

- 检查是否成功写入 CCCD 描述符
- 确认特性是否支持 Notification 权限
- 检查连接状态是否正常
- 查看设备端日志，确认是否在发送数据
