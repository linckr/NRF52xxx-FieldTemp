## 蓝牙温湿度传输方案设计

### 方案概述

考虑到 **nRF52810 内存有限**，我建议使用 **自定义 GATT 服务** 来传输温湿度数据，这样可以最小化内存占用。

### 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    E104-BT5010A 设备                        │
├─────────────────────────────────────────────────────────────┤
│  GATT Server                                                │
│  ├── Environmental Service (自定义 UUID)                    │
│  │   ├── Temperature Characteristic (可读/可通知)           │
│  │   │   └── 数据格式: int16_t (实际值×100)                │
│  │   └── Humidity Characteristic (可读/可通知)              │
│  │       └── 数据格式: uint16_t (实际值×100)               │
│  └── Device Information Service (可选)                      │
├─────────────────────────────────────────────────────────────┤
│  数据流:                                                    │
│  AHT30 传感器 → 3秒采集一次 → GATT 更新 → 通知连接的客户端  │
└─────────────────────────────────────────────────────────────┘
```

### 详细设计

| 项目              | 说明                                            |
| ----------------- | ----------------------------------------------- |
| **服务 UUID**     | `12340001-1234-5678-1234-56789ABCDEF0` (自定义) |
| **温度特性 UUID** | `12340002-1234-5678-1234-56789ABCDEF0`          |
| **湿度特性 UUID** | `12340003-1234-5678-1234-56789ABCDEF0`          |
| **温度格式**      | int16_t, 单位: 0.01°C (例如 2350 = 23.50°C)     |
| **湿度格式**      | uint16_t, 单位: 0.01% (例如 6500 = 65.00%)      |
| **更新间隔**      | 3 秒                                            |
| **传输方式**      | Read + Notify (客户端可主动读取或订阅通知)      |

### 功能特性

1. **客户端读取** - 客户端可随时读取当前温湿度值
2. **自动通知** - 当客户端启用通知后，设备自动推送新数据
3. **LED 指示** - DATA LED 在发送数据时闪烁
4. **低功耗** - 只有在连接状态下才发送通知
