# 离线时间与可靠性收尾（2026-10-16）

用户授权推进六项任务：离线记录时间、App 冷启动离线历史、仓库整理同步 main、生产签名强制校验、诊断回归、精确 OTA 断电矩阵。

## 实施顺序和边界

1. 保全当前未提交整理与取证资料，不把私人数据、私钥或生成产物提交。
2. App 独立从 Room 选择最近保存设备，设备地址就绪时刷新本地历史与曲线；不依赖蓝牙准备或连接。检查设备切换时异步查询覆盖旧数据的风险。
3. Release 移除 Debug 签名回退，生产签名校验纳入产物任务依赖；无生产配置时 Debug 可用、Release 必须失败。验证正式证书和产物。
4. 离线时间需同时设计固件存储/启动会话、协议、App 展示与迁移。无持续供电 RTC 无法恢复任意断电时长。已向用户确认“相对时间＋首次连接校正，未知跨启动时间保留标注”的语义，用户已确认采用此方案。原始历史不全库平移。
5. 对新增功能先检查 App Flash/RAM 和 MCUboot 余量。既有基线 151700 B / 23016 B / 31876 B，必须重新构建核对；不擅改 MCUboot、分区或 UUID。
6. 诊断覆盖权限撤回、手机采样有效性、INIT22、ADC。无法复现或缺少标准电压/仪器时只报告证据边界，不伪称校准与根因已完成。
7. OTA 断电需要实际忙阶段证据与手动电池操作；先备份、验证 SWD 恢复通道，协作窗口外不得触发断电测试。后台 SWD 监测不得与主动调试争用。
8. 整理当前交接状态与历史资料，验证后按用户授权提交并同步 main，核对远端提交。
