# 20260220 - W25Q64 在 nRF52832 上异常排查计划

## 1. 需求背景

- **现象**：同一套代码在 **nRF52810 上运行完全正常**，在 **nRF52832 上**出现：
  - W25Q64 JEDEC ID 读为 `0x00 0x00 0x00`（期望 `EF 40 17`）
  - 写使能失败（写使能后读状态 WEL 未置位，导致页编程返回 -5）
  - 历史存储读到空数据 0xFF（因 Flash 从未成功写入）
- **差异**：52810 使用 **SPI0**（0x40003000），52832 因 I2C0 与 SPI0 共用基址而使用 **SPI1**（0x40004000）；引脚一致：CS=28, SCK=30, MOSI=31, MISO=29。

## 2. 问题分析

| 现象                   | 含义                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| JEDEC ID 全 0          | SPI 读路径异常：MISO 未收到正确数据（若 MISO 浮空多为 0xFF，全 0 多为 MISO 被拉低或 SPI1 未用正确引脚/配置）  |
| 写使能“失败”           | 写使能命令仅发送 0x06，不依赖 MISO；失败是因为**读状态寄存器**得到错误数据（WEL 未置位），根因仍是 SPI 读异常 |
| 52810 正常、52832 异常 | 指向 52832 上 **SPI1 的配置或行为** 与 52810 的 SPI0 存在差异                                                 |

可能原因归纳：

1. **SPI1 未在 Kconfig 中显式启用**：部分构建下 DT 有 `spi1` 但未打开 `CONFIG_SPI_1`，导致驱动未编译或实例错误。
2. **SPI 模式/相位**：W25Q64 使用 Mode 0（CPOL=0, CPHA=0）；若 52832 上 SPIM1 默认与 SPI0 不同，会导致采样/移位错误，读回全 0 或错位。
3. **Pinctrl 未正确应用到 SPI1**：overlay 中虽定义了 `spi1_default_custom`（30/31/29），若合并顺序或 SoC 默认导致 SPI1 仍用默认引脚，则 MISO 可能接到错误 pin。
4. **EasyDMA/实例差异**：nRF52832 的 SPIM1 与 SPIM0 硬件行为一致，但 nrfx 层对 instance 1 的默认配置若有差异，可能影响 transceive。

## 3. 实现方案概述

- **原则**：最小改动、先软件后硬件；同一板子 52810 正常则硬件接线可暂假定正确，重点放在 52832 上 SPI1 的软件配置与一致性。
- **步骤**：
  1. 确认 52832 构建中 SPI1 已启用（Kconfig + 合并后 DTS）。
  2. 在驱动中显式设置 SPI Mode 0，与 52810 行为一致。
  3. 52832 上临时降频（如 1MHz）验证是否为时序/信号问题。
  4. 使用 DT alias `w25q64-spi` 获取 SPI 设备，避免 52832 硬编码 `spi1`，与 overlay 保持一致，便于后续多板型扩展。

## 4. 开发计划列表

- [x] **4.1** 文档：完成本排查计划文档（本文档）。
- [x] **4.2** 配置：为 nRF52832 构建显式启用 SPI1 — 已新增 `boards/nrf52832dk_nrf52832_cpuapp.conf`，内设 `CONFIG_SPI_1=y`。
- [x] **4.3** 驱动：在 `w25q64.c` 中显式设置 SPI 为 Mode 0（CPOL=0, CPHA=0），与 W25Q64 规格一致。
- [x] **4.4** 驱动：W25Q64 初始化时通过 DT alias `w25q64-spi` 获取 SPI 设备（overlay 中 52832→spi1，52810→spi0），去掉 SoC 分支硬编码。
- [ ] **4.5** 可选：52832 上若仍异常，在 overlay 或代码中临时将 W25Q64 SPI 频率降至 1MHz 进行对比测试，并在文档中记录结果。
- [ ] **4.6** 验证：在 52832 上烧录后确认 JEDEC ID 为 EF 40 17、写使能成功、历史存储可写入与读出。

## 5. 当前状态澄清（20260220）

- **初始化流程能跑完**，上层会打印「W25Q64 初始化成功」或「Flash 扫描写头完成」等，但 **写使能失败**，导致 **无法写入数据**（页编程返回 -5，历史存储为 0xFF）。
- 根因未变：52832 上 **SPI 读（MISO）异常** → 读状态寄存器得到错误值 → 写使能后校验 WEL 失败 → 无法写入。需按 4.2 ～ 4.5 做软件修改并验证。

## 6. 用户侧建议（若软件改动后仍异常）

1. **确认板型**：52832 是同一块 E104-BT5010A 换 MCU，还是 nrf52832dk？若为后者，需确认原理图上 W25Q64 是否接在 P0.28/29/30/31。
2. **检查合并后 DTS**：`build_xxx/zephyr/zephyr.dts` 中 `spi@40004000` 的 `pinctrl-0` 是否指向引脚 30/31/29。
3. **硬件**：用万用表/逻辑分析仪确认 MISO (P0.29) 在 JEDEC 读时有波形且非恒低。

## 7. 小结

- 根因集中在 **52832 上 SPI1 的配置或行为** 导致 SPI 读（MISO）异常。
- 软件侧：显式启用 SPI1、统一用 DT alias 取 SPI 设备、显式 Mode 0、可选降频测试。
- 完成 4.2 ～ 4.4 后根据现象再决定是否执行 4.5 及硬件排查。
